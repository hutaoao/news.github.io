9 月 4 日这天前端圈的主线有两条：运行时工具链继续往「把活一次干完」的方向卷，AI 编程工具则进入「模型同质化、改拼工程细节」的新阶段。Bun 在 1.4 大版本后一天内补发 1.4.1 修掉 202 个 issue，Claude Code 出了个专门查「吃上下文不干活」Skill 的 `/skill-doctor`，而 Fastify 和 Hono 同一天各修一个能让前端直接踩坑的安全洞。

### Bun 1.4.1：HTTP/2 进 Bun.serve，动态 import 也能摇树

Bun 在 1.4（Rust 重写）之后一天推出 1.4.1，修掉 202 个 issue。运行时侧：`Bun.serve` 现在能在同一个端口上同时支持 HTTP/2 和 HTTP/1.1，`Bun.write()` 把响应体直接流式写盘而不再先缓冲在内存，WebSocket 客户端新增 `pause()` / `resume()` 做背压控制，并加入 `crypto.argon2`。打包器是本次最大改进——现在能穿透 `import()` 动态导入和 `export * as` 模式做摇树，官方测试里 zod 的产物因此缩小 79%；代码分割产出的 chunk 更少更小，浏览器构建新增 module preloading，200 路由的 React 应用在模拟 4G 下路由切换明显变快。包管理器新增 `bun install --offline` / `--prefer-offline`，workspace 子包现在拥有自包含的 `node_modules`。性能上 Buffer 读写最高快 9 倍、AsyncLocalStorage 快 2 倍。

_来源：[Bun 官方博客 - Bun v1.4.1](https://bun.com/blog/bun-v1.4.1) ｜ [daily.dev](https://daily.dev/posts/bun-v1-4-1-http-2-support-better-tree-shaking-and-202-bug-fixes-nevjtci5m)_

### Claude Code 2.1.261：/skill-doctor 揪出「吃上下文不干活」的 Skill

Anthropic 于 9 月 4 日发布 Claude Code 2.1.261，共 67 项变更（9 项新增、5 项改进、47 项修复），其中 28 项修复落在 VS Code 扩展上。最受关注的是新增 `/skill-doctor` 命令——每个加载的 Skill 都会在每次请求时把描述塞进上下文，但此前无法判断哪些真被调用过；该命令会列出所有已加载 Skill 及其上下文成本，方便裁剪。另外新增 `bashOutputMaxChars` 与 `taskOutputMaxChars` 两个设置项，可把命令与后台任务的内联输出上限提到 128K 字符（超过才落盘），对跑长构建日志/测试输出的团队很实用。企业侧，`/status` 与 `claude doctor` 新增「Organization policy」一行，会说明组织策略为何加载失败（比如代理没放行端点）。此外 `--append-subagent-system-prompt-file` 支持从文件读取过长的子代理系统提示，危险 `rm -rf` 拦截规则扩展到位置参数和双引号 `sh -c` 脚本。注意：提示框的 Ctrl+W / Alt+F / Alt+D 现在对齐 Bash 行为，`keybindingFlavor` 设置已失效。

_来源：[Claude Updates - v2.1.261](https://www.claudeupdates.dev/version/2.1.261) ｜ [releases.sh](https://releases.sh/release/rel_9jMcdiPxGjvPr3c7ZJ04i) ｜ [ClaudeKit](https://claudekit.io/en/updates/claude-code-2-1-261)_

### GitHub Copilot 全量上线 GPT-6 Astra，Codex CLI 与 OpenCode 同日跟进

GitHub 于 9 月 4 日把 GPT-6 Astra 标记为对所有 Copilot 用户正式可用，而 Gemini 3.8 Flash 刚在前一天进入 Copilot——多模型阵容的扩张速度已经按天计算。OpenAI 自家的 Codex CLI 也同步跟上：0.153.3 在 Amazon Bedrock 模型选择器里加入 Astra，0.153.4 修掉了部分用户看不到 Astra 的 bug。SST 出的 OpenCode 在 24 小时内发了两个补丁：v1.18.28 增加 GitHub Copilot session-ID 请求头便于链路追踪，v1.18.29 修了 OAuth 模型过滤逻辑，让 `gpt-6` 这类整数版本号的模型能被正确识别（这正是订阅用户看不到 gpt-6-astra 的原因）。一个明显的信号是：前沿模型在各大助手之间已经按天对齐，接下来比的是输出上限、策略可见性、会话追踪这类工程细节。

### Fastify 5.12.3 修 CVE-2026-18504：根级原始 body schema 会绕过校验

Fastify 于 9 月 4 日发布 5.12.3，修两个安全问题。CVE-2026-18504 是根级原始（primitive）body schema 的场景：路由处理器拿到的可能是未经强制转换的原始值，而不是校验后的值，等于校验形同虚设。CVE-2026-16732 则是在 `trustProxy` 配置了跳数时，`X-Forwarded-*` 头可被伪造。如果你在 Fastify 里用 JSON Schema 做入参校验，尤其是根级直接写 `{ type: 'string' }` 这类原始类型，建议立刻升级。

_来源：[Oday Bakkour - Dev Release Radar September 6, 2026](https://oday-bakkour.com/blog/dev-release-radar-sep-6-2026)_

### Hono 4.13.7 修 JSX XSS：Suspense / ErrorBoundary 里的纯字符串没转义

Hono 在同一天发布 4.13.7，修的是一个典型的 JSX 渲染 XSS：把普通字符串作为 `Suspense`、`ErrorBoundary`、`Context.Provider` 的子节点传入时，输出没有做 HTML 转义。Hono 的 JSX 运行时默认只转义插值表达式，这类「组件 children 直接传字符串」的写法很容易被忽略。只要你在 Hono 的 JSX 里渲染任何用户可控的字符串，都建议尽快升到 4.13.7。

_来源：[Oday Bakkour - Dev Release Radar September 6, 2026](https://oday-bakkour.com/blog/dev-release-radar-sep-6-2026)_

### shadcn/ui CLI 4.21.0：cn 拆成独立包，告别 clsx + tailwind-merge

shadcn/ui 的 CLI 于 9 月 4 日发布 v4.21.0，把几乎每个 Tailwind 项目都要手写一遍的 `cn` 工具函数做成了独立可安装的包，替代 `clsx` + `tailwind-merge` 的组合。执行 `init` 后，`lib/utils` 里现在直接生成 `export { cn } from 'cn'`。值得注意的是 shadcn 默认组件库已在 7 月切换为 Base UI（Radix 仍然完全支持），`cn` 独立成包意味着 shadcn 正在把自己的基础工具层从「复制粘贴的代码片段」逐步收敛为可维护的依赖。

_来源：[Oday Bakkour - Dev Release Radar September 6, 2026](https://oday-bakkour.com/blog/dev-release-radar-sep-6-2026)_

### Prisma 8.0.0-rc.13：.take()/.skip() 正式改名为 .limit()/.offset()

Prisma 8 的 RC 列车继续推进，rc.13 于 9 月 4 日发布。累积下来的破坏性变更已经不少，最需要在 CI 里先查的是集合分页方法重命名——`.take(n)` / `.skip(n)` 现在叫 `.limit(n)` / `.offset(n)`（rc.7 引入）。更早的 rc.4 移除了 `prisma-next.config.ts` 和扁平配置写法（只接受 `prisma.config.ts` + `definePrismaConfig`），rc.5 把 ORM 命令统一到 `db migrate` / `orm init` 并废弃了独立别名。生产环境目前仍建议留在 7.10.0，它提供的 `@prisma/prisma7` 桥接包可以让 Prisma 8 与 7 的 CLI/配置并存，便于分阶段迁移。

_来源：[Oday Bakkour - Dev Release Radar September 6, 2026](https://oday-bakkour.com/blog/dev-release-radar-sep-6-2026) ｜ [Prisma changelog](https://www.prisma.io/changelog)_

### Cloudflare Workers 产物体积上限从 10 MiB 提到 64 MiB

Cloudflare 于 9 月 4 日在变更日志中宣布，Workers 的产物体积上限（未压缩）提升到 64 MiB，并对所有套餐生效，包括免费版。此前免费版是 3 MB、付费版 10 MB（均为压缩后）。这对想往边缘塞打包好的 ML 模型或大型 WASM 二进制的团队是个实质解禁。同一周 Cloudflare 还有另一个动作需要注意：D1 免费层的每日行读/写上限从 9 月 1 日起硬执行，超限后查询会直接报错，直到 UTC 零点重置。

_来源：[Oday Bakkour - Dev Stack Release Audit September 5, 2026](https://oday-bakkour.com/blog/dev-stack-release-audit-2026-09-05) ｜ [Cloudflare Workers changelog](https://developers.cloudflare.com/changelog/)_

### Anthropic：Claude 11 天自主完成费马大定理首个计算机验证证明

Anthropic 宣布 Claude 在基本自主运行 11 天后，完成了费马大定理（FLT）首个端到端、经计算机检查的形式化证明，当日登上 Hacker News。需要说明的是，这不是重新发现数学证明，而是把已有证明转写成 Lean 证明助手能逐步验证的形式。规模相当可观：约 1300 万行 Lean 代码、证明了约 3.03 万个定理（其中约 2.95 万个中间定理最终被纳入完整证明），整个证明仅使用 Lean 的 3 条标准公理，是目前最大的 Lean 证明。对把 Claude Code 指向大型重构或迁移的团队来说，这是个关于「多日自主运行到底能走多远」的有价值数据点。

### Ask HN：MCP 到底谁在真用？

9 月 4 日 Hacker News 上一个提问引发大量讨论：MCP 发布时声量很大，但真实的落地的场景却很难找到。从评论区汇总看，实际在用的场景集中在内部运维诊断、SaaS 集成、语音 agent 和面向客户的聊天机器人——核心收益是省掉了工具发现与集成的开销，比直接接裸 API 或 CLI 省事。反对意见则认为，随着 agent 越来越聪明，直接用 `gh` CLI 就够了，MCP 只是「把 API 文档打包成标准格式喂给 LLM」。一个挺扎心的细节：有人抱怨 Claude 经常忘记自己装了 GitHub 插件，非要折腾半天 `gh` CLI——连模型自己都记不住工具清单时，标准化的发现机制确实还有价值。
