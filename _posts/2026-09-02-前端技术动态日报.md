浏览器端和工具链今天同时有硬货：Chrome 154 带着一批 CSS 细节能力进 Beta，pnpm 12.3 把 catalogs 与 workspace 协议打通，而 CrowdStrike 在 Fal.Con 上发布的能力，直接对准了刚刚折腾完整个前端圈的 npm 供应链投毒。以下是今天的完整盘点。

### Chrome 154 进入 Beta：scroll-marker 支持 tabs 模式，一批 CSS 细节能力落地

谷歌在 9 月 2 日把 Chrome 154（154.0.8037.0）推送到 Windows / Mac / Linux / Android / iOS 的 Beta 通道。开发者侧值得关注的改动集中在 CSS：`scroll-marker-group` 新增 `links` / `tabs` 两种模式，分别对应导航列表与 tablist 语义，两种模式会改变焦点顺序与无障碍角色（tabs 模式下只有激活项是 Tab 停靠点，方向键切换，非激活面板从无障碍树移除），这基本是为「原生轮播 / 标签页」铺路。同批还有 `text-decoration-inset`（控制下划线等装饰相对文字边缘的内缩或外延，支持 auto / 长度 / 百分比及双值语法）与 `text-decoration-skip-spaces`（让装饰线跳过空白字符），两者都是在替代过去要靠 background 渐变或额外元素 hack 的写法。

JavaScript 侧是 TC39 的 **Iterator.includes**，可以像数组一样判断迭代器是否产出某个值。Web API 方面，WebSocket 构造函数支持传 options 字典（`new WebSocket(url, { protocols: "soap" })`）作为后续扩展点；WebCrypto 加入后量子密码算法与一个对称 AEAD；CSS Typed OM 的 `CSSStyleValue` 体系（含 `CSSKeywordValue`、`CSSUnitValue` 等）终于在 Worker 上下文暴露。另外 popover / dialog 的 light dismiss 改为基于 click 事件，触屏滚动与右键不再误触发关闭。

_来源：[Chrome for Developers - Chrome 154 beta](https://developer.chrome.com/blog/chrome-154-beta) / [Chrome Releases Blog](http://chromereleases.googleblog.com/)_

### pnpm 12.3 发布：catalogs 打通 workspace: 协议，一批 CLI 与全局路径修复

pnpm 12.3.0 于 9 月 2 日上线（12.3.1 紧随其后）。这个小版本的主线是 **catalogs 现在可以通过 `workspace:` 协议解析 workspace 内部依赖**，此前 catalogs 与 workspace 协议之间有一道口径不一致的墙。性能上，大仓库里具名的 `workspace:*` / `workspace:^` / `workspace:1.2.3` 依赖现在只解析一次并跨所有声明它的项目复用，不再逐项目重复解析；workspace 项目发现也改为并发探测 + 并行读取 package.json。

修复列表相当长：`pnpm audit --fix` 不带值时报 `ERR_PNPM_INVALID_FIX_OPTION` 的问题（含后面跟其他 flag 的情况）、`--fix=override` 忽略 `saveExact` / `savePrefix` 的问题都已解决；`nodeDownloadMirrors` 的 Node 运行时下载现在复用 URL 作用域的 npm registry 凭据（bearer / basic / tokenHelper），私有镜像场景终于能过鉴权；并发安装共享全局 virtual store 时的 `ERR_PNPM_CMD_SHIM_CHMOD` 竞态、Windows 上 `npm install -g pnpm` 生成的 PowerShell shim 未调用原生 exe、WSL2 下全局 shim 的分发路径，也都修了。另外配置值里的非 ASCII 字符在环境变量替换时不再被破坏（`storeDir: ./café-store` 这类路径可正常保留），`globalDir` / `globalBinDir` 无论在哪里设置都会被正确采纳。

_来源：[Release Watcher - PNpM CLI](https://rwatcher.yadoc.fr/components/397561b1-1dae-485c-9c98-04e8814675c5/8fd5590e-4501-4579-94db-25ad981349e2) / [endoflife.date - pnpm](https://endoflife.date/pnpm)_

### CrowdStrike 发布实时供应链攻击防护，在端点拦下恶意 npm / pip 包

CrowdStrike 在 9 月 2 日的 Fal.Con 2026 上推出 Real-Time Supply Chain Attack Protection，把开源供应链的风险控制点放到了端点。思路很直接：投毒包无论伪装得多正常，最终都要在端点上执行代码，而 Falcon sensor 恰好已经守在那里——所以它在 `npm install` / `pip install` 这类包管理器事务上做拦截，在**任何内嵌脚本运行之前**就切断，覆盖 Windows / macOS / Linux 上的 npm 与 PyPI。官方强调这不需要新 agent，也不只是保护开发机，而是覆盖所有运行 agentic 应用的端点。

配套能力包括：可设置最小包年龄等细粒度策略（直击「刚发布几小时的投毒版本」这一最常见向量）、触发后自动跨所有端点回溯并走 Charlotte Agentic SOAR 做修复、以及全局包清单便于被攻陷时快速定位影响面。CrowdStrike 在发布里援引了自家 2026 威胁狩猎报告的数据——朝鲜背景的 STARDUST CHOLLIMA 投毒了 131 个 AI 框架包，eCrime 组织 ALTERED SPIDER 曾在一天内攻陷 300 多个软件依赖。对前端团队来说，这条线的意义在于：供应链防御正在从「registry 侧扫描」向「执行侧拦截」迁移。

_来源：[CrowdStrike 新闻稿](https://www.crowdstrike.com/en-us/press-releases/crowdstrike-extends-its-endpoint-advantage-to-secure-software-supply-chain/)_

### Vercel 新项目中间件默认运行时从 Edge 切到 Node.js

自 2026 年 9 月 1 日起，Vercel 上新建项目的 middleware 默认运行时由 Edge 改为 **Node.js**，Edge 运行时对新项目标记为 deprecated。如果你确实还需要 Edge，可以在 `vercel.json` 里显式钉住：

```json
{
  "functions": {
    "middleware.ts": { "runtime": "edge" }
  }
}
```

同批 CLI 改动：多服务构建时，每行构建输出会带上 service 标签前缀，便于在多服务项目里分辨日志来源。需要提醒的是，这一变更与仍在影响面的 **CVE-2026-23869**（App Router Server Functions DoS，CVSS 7.5）叠加——如果你的中间件承担了鉴权或限流职责，建议借这次切换重新核对一遍：攻击者构造特定 HTTP 请求打到 Server Function 端点，会在反序列化阶段触发过量 CPU 消耗，13.x–16.x 全线受影响。Vercel 托管项目前有 WAF 规则兜底，**自部署团队必须自己升级**（Maintenance LTS 最低 `next@^15.5.15`，Active 线最低 `next@^16.2.3`）。

_来源：[Oday Bakkour - Dev Stack Release Audit 2026-09-02](https://oday-bakkour.com/blog/dev-stack-release-audit-2026-09-02) / [Vercel CVE-2026-23869 说明](https://vercel.com/changelog/summary-of-cve-2026-23869)_

### Claude Code 2.1.259：新增 managedMcpServers 托管配置

Claude Code 在 9 月 2 日推送 2.1.259（次日进入各发版追踪站），本次变更的核心是一项组织级管控能力：新增 `managedMcpServers` managed setting，让管理员可以在组织维度统一管理 MCP 服务器的可用清单，而不用再依赖每个开发者本地的 `.mcp.json`。对于已经在团队里铺开 MCP 的前端组，这补上了此前缺失的「服务端治理」一环——尤其是在过去两周 npm 供应链投毒专门往 `.claude/settings.json` 里塞 SessionStart hook 的背景下，托管式配置本身就是一种收敛攻击面的手段。

_来源：[Havoptic - Claude Code v2.1.259](https://www.havoptic.com/r/claude-code-2.1.259) / [Claude Code CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)_

### Google Antigravity CLI 1.1.24：修掉 agent 重复出现与管道挂起

同日在 AI 编程工具线上，Google 的 Antigravity CLI 发布 1.1.24，主要修两类问题：agent 在选择器里重复出现（同一 agent 被列出多次），以及 CLI 通过管道输出给其他命令时会挂起。另外修复了若干配置解析相关的缺陷。这两类 bug 都属于「不影响功能但严重破坏日常手感」的类型，对把 agent 串进脚本流水线的团队影响更明显。

### Auth.js 转入维护模式，Better Auth 团队接手

Auth.js（原 NextAuth.js）现由 **Better Auth** 团队维护，从 2026 年初起进入 maintenance mode——只收安全补丁，不再有新功能；所有新特性都发生在 Better Auth 一侧，后者已超过 26,000 GitHub star、周 npm 下载 15 万。官方给出的建议很明确：启动新的 Next.js / SvelteKit / Nuxt 项目应默认选 Better Auth；已有的 Auth.js 集成仍会获得安全修复，但不要指望它再有新能力。

这是一个值得记一笔的生态位交接。Auth.js 长期是 Next.js 生态的默认鉴权方案，转入维护模式意味着 App Router + Server Actions 时代的新范式适配会集中在 Better Auth 身上；正在做技术选型的团队需要把这一点纳入评估。

_来源：[Better Auth 公告](https://better-auth.com/blog/authjs-joins-better-auth) / [Oday Bakkour 审计](https://oday-bakkour.com/blog/dev-stack-release-audit-2026-09-02)_

### Prisma ORM 7.10：为 Prisma 8 铺一座桥

Prisma ORM 7.10.0 引入 `@prisma/prisma7` 兼容包，允许项目在装 Prisma 8 的同时保留一套版本匹配的 Prisma 7 CLI 与配置，用于分阶段迁移：

_来源：[Prisma Changelog](https://www.prisma.io/changelog) / [Oday Bakkour 审计](https://oday-bakkour.com/blog/dev-stack-release-audit-2026-09-02)_

### Cloudflare D1 免费套餐开始强制执行每日行数上限

自 9 月 1 日起，Workers Free 套餐下的 D1 查询在账户超出当日行读取或行写入上限后会**直接报错**，Workers Binding API 与 REST API 都一样，直到午夜 UTC 重置；Cloudflare 会在触顶时发邮件告警。免费层团队应提前给查询加索引、消灭全表扫描：

```sql
EXPLAIN QUERY PLAN SELECT * FROM events WHERE user_id = ?;
-- 计划里出现 SCAN 而非 SEARCH 时补索引
CREATE INDEX idx_events_user_id ON events(user_id);
```

长期贴近上限的项目应考虑升级到 Workers Paid。相关地，workerd 也发了 v1.20260901.1，用 TypeScript 实现了 `FileSystemWritableFileStream`，补了编码与压缩流的测试套件，并修复了初始化失败时 SQLite 句柄泄漏。

_来源：[Cloudflare Workers Changelog](https://developers.cloudflare.com/workers/platform/changelog/) / [workerd v1.20260901.1](https://github.com/cloudflare/workerd/releases/tag/v1.20260901.1)_

### Vercel 推出 Fluid：把构建、沙箱与函数统一到一套计算系统

Vercel 于 9 月 1 日发布 **Fluid compute**，取代此前构建、沙箱、函数各自为政的原语，改为按需组装机器的单一计算系统。对部署在 Vercel 上的前端项目，这意味着构建与运行时的资源调度不再割裂，冷启动与并发模型有望统一。同期 Vercel 还向 Pro / Enterprise 开放了 AWS PrivateLink，让 Functions 与构建可以不经公网访问 AWS 上的服务。

### Vercel Labs 的 portless 登上 GitHub Trending：用命名 .localhost 域名取代端口号

Vercel Labs 的 **portless** 在 9 月 2 日 GitHub Trending 日榜拿下 69 星（总 11.6k），它解决的是一个长期被忍受的小痛点：把 `http://localhost:3000` 换成稳定的 `https://myapp.localhost`。用法是 `"dev": "portless run next dev"`，代理会自动启动、给应用分配 4000–4999 的随机端口，并处理 TLS（首次运行生成并信任本地 CA、绑定 443）。

有意思的是它对框架差异的处理：Next.js、Express、Nuxt 等读 `PORT` 环境变量即可，而 Vite、Astro、React Router、Angular、Expo 这类忽略 `PORT` 的框架，portless 会自动注入正确的 `--port` / `--host`，且能穿透 package script。它还明确面向 agent 场景做了适配——提供 agent-readable 文档，在无 TTY 或 `CI=1` 环境下带描述性错误退出而非阻塞等待。目前项目仍是 pre-1.0（最新 v0.15.6）。

_来源：[GitHub - vercel-labs/portless](https://github.com/vercel-labs/portless)_
