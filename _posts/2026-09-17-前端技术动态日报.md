今天的重心明显从「框架发版」挪到了「工程底座」：浏览器侧 Chrome 155 进 Beta，语言侧 Rust 同时出现在 GPU、编辑器运行时和代码编辑器三条战线上，安全侧则出现了第一个把浏览器内置 AI 助手当成攻击面的系统性研究。

### Chrome 155 进入 Beta：CSS symbols()、corner 简写、JPEG XL 借 Rust 回归

Chrome 155 于 9 月 16 日推送到 Beta 通道（桌面版 155.0.8059.5，Android 155.0.8059.4，iOS 155.0.8059.2）。CSS 侧一次加了四件实用的东西：`symbols()` 允许内联定义计数器样式而不用先写 `@counter-style`；`corner-*` 系列简写把 `border-radius` 和 `corner-shape` 合并到单个声明里；`text-decoration-skip-spaces` 让下划线跳过空白；`margin-trim` 裁掉容器首尾子元素的margin。JS 侧最值得关注的是**模块加载失败不再被永久缓存**——之前 `import()` 失败后重试会立即失败，现在可以手动重试，对弱网场景是实打实的修复。

Web API 方面新增窗口控制（`maximize()` / `minimize()` / `restore()` / `setResizable()` 以及 `display-state`、`resizable` 媒体特性）、WebCrypto 加进 ML-KEM、ML-DSA、ChaCha20-Poly1305、X-Wing 等后量子算法、Digital Credentials 支持签发。最戏剧性的一条是 **JPEG XL 解码回归 Blink**，而且用的是 `jxl-rs`——一个内存安全的纯 Rust 解码器。同一天 Chrome 154 也向小比例桌面与 Android 用户开始 Early Stable 推送，正式转正定在 9 月 22 日。

_来源：[Chrome 155 beta（Chrome for Developers）](https://developer.chrome.com/blog/chrome-155-beta)、[Chrome Releases](https://chromereleases.googleblog.com/2026/09/)_

### GitHub 用 Copilot 把 Copilot 的运行时重写成 83 万行 Rust

GitHub 工程师 Stephen Toub 在官方博客复盘：团队用 Copilot 应用和 Copilot CLI，把支撑 Copilot CLI、Copilot 应用、Copilot SDK 以及 VS Code、Excel、Word 等一众产品的 agent runtime，从 TypeScript / Node.js / V8 整体重写为 **832,378 行生产级 Rust + 468,689 行 Rust 单元测试**（TypeScript 降到 0）。窗口是约 14.5 周，拆成 **128 个 PR 增量合入 main**，期间主干照常发布了 135 个版本（含 100 个预发布），用户无感知。

比数字更有信息量的是账本和工程取舍：token 账单约 12 万美元、提示词缓存命中率 96.22%、上下文自动压缩 5,116 次；作者按 PR 占比估计自己只投入约三周。诊断分布也很反直觉——87.1% 的 `cargo check` 直接通过，报错里 37% 是命名与导入解析、22% 是缺失方法或字段，而**所有权/借用/生命周期类错误只占全部带错误码诊断的 1.7%**。收益侧，十客户端批次里驻留私有内存峰值从旧实现的 1,383 MB 降到进程外 247 MB / 进程内 126 MB。Toub 自己划的线同样值得记：「这不是在说所有大型 TypeScript 程序都该改成 Rust」，迁移刻意保持行为不变。

_来源：[Migrating the GitHub Copilot runtime to Rust, using Copilot（GitHub Blog）](https://github.blog/ai-and-ml/generative-ai/migrating-the-github-copilot-runtime-to-rust-using-copilot/)_

### NVIDIA 官宣 CUDA Rust：用 Rust 直接写 GPU 内核

NVIDIA 在开发者博客宣布正式投入 Rust 原生 GPU 编程，采用与 CUDA 本身对称的两条轨道：**SIMT** 对应你已经熟悉的 CUDA C++ 模型，走 `cuda-oxide`——一个自定义 rustc 代码生成后端，内核直接编译成 PTX 而不是包装层；**Tile** 则是较新的按块编程模型，由 Tile IR 编译器决定图块如何映射到各代架构，源文件不编码架构选择。NVIDIA 明确 CUDA C++ 和 CUDA Python 仍是企业级主线，CUDA Rust 会在 2027 年及以后逐步成熟。

这条官方消息发布后在同一天登上 Hacker News 榜首（642 分、245 条评论），讨论焦点集中在两点：一是 NVIDIA 自己的 Nova 驱动、Dynamo 推理框架本就写的 Rust，内核是最后一块缺口；二是「内存安全 + 零成本抽象」能否真的吃到 GPU 编程这块最依赖手工优化的领域。

_来源：[Introducing CUDA Rust: Two Tracks for Writing GPU Kernels（NVIDIA Developer）](https://developer.nvidia.com/blog/introducing-cuda-rust-two-tracks-for-writing-gpu-kernels/)_

### Zed 发布 Delta 公测：用 thread 取代 Pull Request

Zed 把 Delta 推向公测，口号直接对着 GitHub：**PR 在 agent 时代已经不合时宜**。核心理由是时间尺度错配——PR 是为「人类成批写代码然后停下来等评审」设计的，而 agent 是连续、并发地产出改动，把数据流塞进「分支→提交→开 PR→等评审→合并」的批处理会杀掉反馈回路。Delta 的做法是多人共享的 thread：邀请同事进入你与 agent 的对话，他能看到同一批 worktree、能直接问 agent「为什么这里用 Mutex 而不是 RwLock」、能开独立的评审子 thread（带隔离的 worktree 副本）改代码，而不打扰原作者。

底座是 DeltaDB：在 Git 的基于内容寻址之外，额外记录 commit 之间的增量版本、以及人类和 agent 的消息，让「代码是怎么演化到这一步的」变成可查询的。Zed 表示自家 Delta 仓库已经关掉 PR，33 个人靠 thread 合入了 570 个改动，并称「几个月内」会在内部开发上彻底离开 GitHub；但主开源的 zed 仓库仍留在 GitHub，因为社区入口不是能随便搬的。CI、issue、存储目前都还是外部依赖，路线图上排着基于 GitHub 权限的仓库访问、agent 沙箱、Claude Code 插件与 MCP 支持。

_来源：[Replace PRs with Delta – Now in Public Beta（Zed Blog）](https://zed.dev/blog/delta-public-beta)、[The New Stack 报道](https://thenewstack.io/zed-delta-github-alternative/)_

### BragJack：一个普通浏览器扩展就能劫持五款产品的内置 AI 助手

Forever Security 的研究员 Gal Weizman 公布 BragJack——**一个扩展**即可接管 Gemini Live in Chrome、Microsoft Edge、Opera Neon、Perplexity Comet 和 Claude in Chrome 的内置 agent，且安装之后**零点击**即可生效。他给这套手法起名「Prompt Forcing」：不同于 prompt injection 要在文档或网页里藏指令，攻击者直接夺取 agent 与浏览器之间的通信通道，自己撰写完整指令、自己决定何时投喂、自己追加 follow-up，「比 prompt injection 危险得多」。

根因是同一个架构选择：agentic 浏览器把「身体」（能读文件、开摄像头、截屏、操作标签页）和「大脑」（跑在厂商云端的受信页面）拆开后，允许扩展通过未做严格来源校验的通道去接触那个受信页面。具体路径各不相同：Chrome 用 DNR 弱化 CSP 并劫持加载 Gemini 的 WebView 的 JS，脚本再向特权 `chrome://glic` 接口发指令；Edge 得链两个弱点，先注入一个有 prompt 权限的微软推广页，再用「Think→Do」模式切换的竞态绕过网络层防护；Comet 最惨，Perplexity 主域挡了扩展，但代码里残留的 `testing.perplexity.com` 没锁死，被拿掉重定向头后注入代码。

Google 与 Microsoft 已分别以 CVE-2026-0628（Chrome 143.0.7499.192 修复）和 CVE-2026-55945（Edge 150.0.4078.48 修复）发布公告，其余三家也已调整实现。五家合计支付了约 2 万美元赏金（Google 与 Perplexity 各 7,000、Microsoft 5,000、Opera 900、Anthropic 600）。截至 9 月 16 日，两条 CVE 都未进入 CISA 已知被利用目录，也未见在野利用。

_来源：[BragJack Attack Can Turn a Browser's Agentic AI Against It（Dark Reading）](https://www.darkreading.com/endpoint-security/bragjack-browser-agentic-ai)、[BragJack 技术总览（Forever Security）](https://www.worldprogramming.org/posts/bragjack-prompt-forcing-in-browser-ai-agents-via-browser-extensions-qf6at4)_

### Cloudflare 开源 security-audit-skill，直接冲上 GitHub Trending 榜首

Cloudflare 把内部漏洞发现平台的起点——一套 `SKILL.md`——以 MIT 协议开源，当天 GitHub Trending 第一（单日 +3,606 星）。它不是又一个扫描器，而是把六阶段审计流程塞给编码 agent：侦察（并行研究 agent 映射架构与信任边界，产出 `architecture.md`）→ 按覆盖率分工打猎（注入、访问控制、业务逻辑、密码学、功能滥用、链式攻击加一个 wildcard）→ 独立验证 → 人读报告 → 结构化输出 → 独立复核。

两个设计细节最值得抄。第一，**确认漏洞的 agent 永远不是发现它的那个**——每个候选交给全新 agent，任务只有「证伪」，证伪不了才标 `confirmed`，否则进 `needs_validation` 并写清未决事实，或进 `rejected` 并记录为什么被推翻。第二，产出的是对着 JSON Schema 校验的 `findings.json`，配零依赖校验脚本，「有没有看过这块」从感觉变成可查询的 coverage ledger。官方还诚实写了一条：单次运行大约只能找到多次运行总量的**一半**漏洞，所以多次跑是累加的。

_来源：[cloudflare/security-audit-skill（GitHub）](https://github.com/cloudflare/security-audit-skill)_

### 阿里 open-code-review 连续两日霸榜：用约 1/9 的 token 换更少的误报

阿里内部跑了两年的代码评审工具 `alibaba/open-code-review` 9 月 17 日继续位居 GitHub 热榜前列（单日 +3,290 星，累计约 3.3 万）。架构是两条线并行：先跑一遍确定性规则流水线，把 NPE、线程安全、XSS、SQL 注入这类确定性问题筛掉，再让 LLM 智能体补上「必须看上下文才能判断」的那一层，最终给出精确到行的批注，兼容 OpenAI 与 Anthropic 两家模型。

官方给出的口径是：在同样基座模型下 F1 更高，token 消耗只有约 1/9——这是**故意用精度换召回**，宁可少报也不制造噪音。这一点与 Cloudflare 那份技能的设计哲学正好互相印证：agent 生成的代码越来越多，瓶颈已经不是「写得快不快」，而是「谁来判断对不对」。

### Node.js 26.9 之后的动作：`util.debounce()` 进主线，Node 27 要硬拒超量响应头

Node Weekly 第 641 期整理了这一周 Node 侧的变化。运行时层面，`node:ffi` 默认开启（仍实验）、`node:bench` 是新基准测试模块、Web Workers 有了实验实现、worker 线程启动快了一倍。核心模块层面，**`util.debounce()` 与 `util.throttle()` 已合入 main**，将来不必再引第三方工具库。行为变更上有一条需要注意：**Node 27 里 HTTP 客户端会对响应头数量超过 `request.maxHeadersCount`（默认 1000）的响应直接报错，而不是像现在这样静默截断**。安全侧，仍在「维护模式」但周下载 2,500 万的 moment 发布了 2.31.0 修路径穿越。另外 Node.js Web 团队重新设计的 API 文档已合并，会随某个版本上线。

### Vue core 同日两个真 bug 的修法：循环引用与 v-once 卸载

Vue 核心仓库 9 月 17 日合入两处渲染/响应式修复，都值得看一眼根因。其一，`looseEqual` 自从支持 Map/Set 递归后，只要 option 值是互相引用的对象集合，组件挂载时就会抛 `RangeError: Maximum call stack size exceeded`；修法是给递归穿一个对象对的栈，遇到已访问过的对就判定相等，循环结构不再无限递归。其二，父组件重渲染之后再卸载，会跳过嵌在 `v-once` 里的子组件；修复在克隆 vnode 时保留了 block 的 `hasOnce` 标记与缓存索引，teardown 只清当前组件自己的缓存，避免移除一个 slot 实例时连带失效另一个（对应 `nuxt/nuxt#32154`）。同批还有 `vitest` 升到 4.1.11 的 security 依赖更新，以及把仓库自身锁定的 pnpm 从 11.19.0 跳到 12.4.2。

_来源：[looseEqual handles cycles, v-once children unmount correctly（RepoJournal）](https://repojournal.com/showcase/vuejs/2026-09-17/looseequal-handles-cycles-v-once-children-unmount-correctly)_

### Meta 发布 WhatsApp Business Tools MCP：让编码 agent 直接开局

Meta 推出 WhatsApp Business Tools MCP 服务器，把过去必须在开发者控制台、Business Manager、API 文档和编辑器之间来回跳的建号流程，收进一次对话：agent 可以创建 WhatsApp Business 账号、添加并 OTP 验证号码、把号码注册到 Cloud API、检查服务条款／支付方式／企业验证等前置条件（缺哪项就给直达链接）、按描述生成或修改消息模板并给出审核状态、从已注册号码发测试消息、配置 webhook 的回调 URL 与字段订阅。可接入 Claude、Cursor、Codex、ChatGPT。
