今天是浏览器和运行时的双重更新日：Chrome 153 正式进 Stable，Chrome 十八年来第一次把大版本节奏压到两周；Node.js 同一天推出现货 LTS v24.21.0。另一边，AI 编程工具集体加速——Claude Code 一天发两版，还因为偷偷给 git commit 加署名被挂上了 Hacker News。

### Chrome 153 进 Stable：Chrome 正式进入双周发布时代

Google 于 9 月 8 日（周二）把 Chrome 153 推送到 Windows、Mac、Linux 与 Android 的 Stable 通道，桌面版为 153.0.8010.36/.37，Android 同为 153.0.8010.36。这是 Chrome 历史上第二次提速——2021 年从六周改四周，现在直接砍到两周，Chrome 154 已定档 9 月 22 日。Google 给出的理由是缩短「N-day」补丁窗口：攻击者也在用 AI 加速写利用代码，四个月的等待期太长了。本次更新打包了 **230 个安全修复**，其中包括 4 个 WebGL 相关的 Critical 级漏洞（CVE-2026-87464、CVE-2026-87488、CVE-2026-87438、CVE-2026-87527）。功能层面，153 带来原生 IAMF 3D 空间音频解码、**用 Rust 重写的 XML 解析器**（legacy XSLT 除外）、CSS 单轴滚动容器优化（跳过交叉轴布局，消除横向轮播的微卡顿），以及 `chrome.publicSuffix` 扩展 API。企业用户可继续留在八周一更的 Extended Stable 通道。

_来源：[Chrome Releases 官方博客](https://googlechromereleases.blogspot.cz/) · [Chrome Unboxed](https://chromeunboxed.com/chrome-153-launches-today-googles-accelerated-2-week-release-cadence-begins/) · [IT之家](https://www.ithome.com/0/999/947.htm)_

### Node.js v24.21.0「Krypton」LTS 发布

Node.js 24 线同日推出 v24.21.0。依赖层面升级到 OpenSSL 3.5.8、根证书 NSS 3.126、Undici 7.29.1；功能上有四个 SEMVER-MINOR：`perf_hooks` 直方图内置统计假设检验（配合 `compare.js` 新增的 `--analyze` 模式，让 CI 上的「快了 5%」不再靠肉眼判断是真是噪）、`util.MIMEType.parse` 的非抛出版本、`net.BlockList` 性能优化、以及通过 STORE loader 加载私钥的 crypto 支持。对做性能回归门禁的团队，这套直方图 + `--analyze` 组合比继续在共享 CI 机器上比数字靠谱得多。

_来源：[GitHub Release](https://newreleases.io/project/github/nodejs/node/release/v24.21.0) · [Devtalk](https://forum.devtalk.com/t/node-js-v24-21-0-released/249562)_

### Vercel 推出 Flat Rate CDN，Pro 团队告别按量账单

Vercel 把 Pro 团队的 CDN 计费从按量改为**固定月费**，覆盖 CDN 请求、流量与可观测性，套餐内含 100 万次请求与 1TB 流量。这是 Vercel 近一个月第 6 次价格调整——9 月 1 日刚改过 Hobby 与 Pro 的额度口径，9 月 3 日又引入 Basic 构建机（2 vCPU / 8GB）。对流量波动大、被「惊喜账单」吓过的团队，固定费率是明确的利好；但按量更省的中小站点需要注意自己是否跨过了盈亏线。

_来源：[Vercel Blog](https://vercel.com/blog/introducing-flat-rate-cdn) · [Changelog](https://vercel.com/changelog/flat-rate-cdn-is-now-ga-for-pro-teams)_

### Vercel Sandbox 域名解析改走区域副本，全球路由快 18 倍

同日另一条 Vercel 更新：Sandbox 的公开域名不再从中心化存储解析，改为**从区域副本解析**，中位查询延迟下降使全球路由速度提升约 18 倍。这条对用 Vercel Sandbox 跑隔离执行环境的场景（比如 9 月 3 日上线的 Cursor Cloud Agents 集成）是直接的体感改善。

_来源：[Vercel Changelog](https://vercel.com/changelog/vercel-sandbox-routing-is-now-18x-faster-globally)_

### Claude Code 一天两版：2.1.265 加插件目录，2.1.266 紧急修回归

Claude Code 在 9 月 8 日连发两版。v2.1.265 让 `--plugin-dir` 支持**指向整个文件夹**——子目录里带 manifest 的各自作为独立插件加载，会话运行中增删子目录即时生效，不必重启；`/workflows` 的 agent 详情视图现在能逐个显示工具调用的运行/失败/完成状态，子智能体自己的任务列表也会并排展示；工具结果上限设为 1GB。但 2.1.265 引入了一个严重的回归：未文档化的 `CLAUDE_CODE_USE_GATEWAY` 环境变量原本只在同时设置 `ANTHROPIC_BASE_URL` 与 `ANTHROPIC_AUTH_TOKEN` 时才生效，新版本却开始仅凭它自己就强制走 Cloud 网关登录，导致所有自建 LLM 网关/代理配置全线报「Not signed in to the Cloud gateway」。v2.1.266 当天回滚了这一行为，**升级即可恢复，无需改配置**。

_来源：[Havoptic v2.1.266](https://www.havoptic.com/r/claude-code-2.1.266) · [Claude Code Daily Briefing 9/9](https://claude-news.today/en/briefings/briefing-2026-09-09)_

### npm 蠕虫「原样复用」旧载荷重现，Aikido 披露

Aikido 分析师发现，一个沉寂了 **111 天**的 npm 蠕虫载荷重新出现：9 月 7 日一小时内由同一个 npm 账号上传了 4 个包版本，其恶意文件的 SHA-256 与 5 月 19 日针对 @antv 系列包的攻击中观察到的文件**完全一致**——既没有重新打包，也没有做轻微改动。这让事件变成对「已知恶意软件检测能力」的直接测试，而不是新型规避手法的较量。载荷在 install 阶段启动，能对 npm 注册表验证被盗令牌、下载包归档、插入代码、提升版本号并重新发布，把单个被攻陷的开发者账号迅速放大成供应链问题。npm 在 7 月引入了发布时扫描（包会被暂扣一段时间），但显然仍未拦住精确哈希匹配的已知样本。

_来源：[网易科技（转 Cyber Security News / Aikido）](https://www.163.com/dy/article/L6AHTRFM05561FZY.html)_

### CodePen 被曝未保存也实时上传编辑器内容

有开发者在 Hacker News 上报告：在 CodePen 编辑器里输入的内容会在 1–2 秒内被发到 codepen.dev，**即使你没有点保存**。测试方法是在 index.html 里输入一个唯一标识符，随后在生成的预览 HTML 中逐字找到它，构建日志显示 `save:false`。这意味着如果你在编辑器里误粘了密钥或密码，即便从未发布也可能已经泄露。目前仍是单方面的测试报告，CodePen 未作官方回应——但结论很直接：**别在带实时同步的在线编辑器里输入敏感信息**。

### 阿里开源 open-code-review：确定性工程 + LLM 混合架构

阿里开源了内部官方 AI 代码审查助手 open-code-review（Go，Apache-2.0），源自服务数万名开发者、识别数百万缺陷的内部系统，开源不到一个月冲到 18k+ Star。它针对纯语言驱动审查的三个老毛病——**覆盖不全**（30 个文件只审 5 个）、**位置漂移**（行号对不上）、**质量随提示词波动**——采用混合架构：能用工程保证的步骤（diff 解析、文件映射、行号对齐）绝不让模型猜，模型只负责判断缺陷本身。这个思路和本周 Anthropic「安全是代码不是提示词」、Spotify「Hook 管底线」的经验是一致的。

### SWE-Bench ProMax：仓库级重构最佳解决率仅 41.2%

本原智数与 SWE-Bench ProMax 团队（已被 COLM 2026 接收）推出面向大规模多语言代码重构的 Benchmark：v1 含 170 个真实 GitHub 任务、覆盖 7 种语言、平均修改 11.4 个文件，而前沿模型的最佳解决率只有 **41.2%**。把评测从「单文件补全」拉到「跨文件、多语言、仓库级重构」之后，结果说明当前模型在真实工程重构上远未饱和——41.2% 是能力天花板而不是及格线。对采购与选型的现实意义是：宣称「能写码」的 Agent 在遇到真实 repo 级改动时仍会频繁失败，落地应以人机协同 + 强回归测试为前提。

_来源：[AI 日报 2026-09-08](https://juejin.cn/post/7682710321413619758)_

### Dan Luu 万字实测：让 Agent 用 TDD、形式化方法，效果还不如不指挥

知名工程师 Dan Luu 发布大规模实证：让 Codex（GPT-5.6 Sol）在 Rust 上实现 Zstd，对比 30 种测试/验证条件（TDD、Lean 4、QuickCheck、属性测试、Fuzzing、Kani、TLA+、Verus 等），每种跑 80 次。结论反直觉：**没有任何方法显著跑赢「无附加指令」的默认组**；TDD 表现如预测般糟糕；Agent 用形式化方法时只证明无关属性，用属性测试时大量生成无效随机输入去测平凡性质——「它们要么照写平时的测试塞进新框架，要么表面用技术、实际拿不到技术的价值」。Codex 推荐的热门测试 Skill（25 万星）同样跑输，而一个专门引导 Agent 偏离默认行为的自定义小 Skill 反而有效。

_来源：[danluu.com](https://danluu.com/agentic-testing) · [AI 技术日报 2026-09-08](https://www.cnblogs.com/itech/p/22895972)_
