今天国内有一条分量很重的政策：工信部印发《「人工智能+软件」专项行动实施方案》，把「智能体软件」和「技能包（Skills）资源库」第一次写进国家级产业规划。海外这边，SvelteKit 3 进入 RC、Claude Code 把并发智能体上限悄悄提到 256、Copilot 代码审查换成多智能体 ensemble——前端和 AI 编程工具在同一天各推了一步。

### 工信部印发《「人工智能+软件」专项行动实施方案》，「智能体软件」首次写入国家级政策

9 月 11 日，工业和信息化部对外发布《「人工智能+软件」专项行动实施方案》，提出到 2030 年关键软件全面实现智能化升级，智能编程、智能体软件及智能服务等新业态成为产业新增长极，并建成若干具有国际影响力的开源社区和产业集群。2028 年的阶段目标是：推广应用覆盖 **2 万家**规模以上软件企业、累计组织实施 **100 项**软件企业智能化技改项目、在重点行业打造 **100 个**智能体软件标杆应用、孵化 **5 个以上**优质开源项目。方案围绕六个方面部署，其中与前端开发者最直接相关的两条是「发展智能体驱动的智能编程工具」和「**推动建设智能体软件应用商店和技能包（Skills）资源库**」——后者与国际上 Agent Skills 生态的演进方向几乎同步，意味着「技能包」这一形态开始有了标准话语权的争夺。方案还要求「提升软件领域安全保障能力」，在开发环节以智促安，在产品环节强调行为可控、全程可溯；落地机制上依托「揭榜挂帅」、首版次软件产品认定和财政专项资金。

### Svelte 发布 9 月月报：SvelteKit 3 进入 Release Candidate

Svelte 团队的 9 月月报确认 **SvelteKit 3 已达 Release Candidate**，距离正式版一步之遥。这是一个真正的 major：配置从 `svelte.config.js` 迁到 `vite.config.ts`，`$lib` 别名重命名为 `#lib`（改用 Node subpath imports），远程表单新增 `submitted` / `field.touched()` / `dirty()` 助手，浅层路由内置进 `goto` 的 state 选项，变量配置正式脱离 experimental，并会检测新部署（数据、remote、表单 action 响应以及 tab 聚焦、可见性变化时）。工具链侧，`sv` CLI 用更宽的 **ai-tools** 插件取代了原来的 `mcp` 插件（可为 Claude Code、opencode 配置 Svelte 插件，或按客户端挑选 MCP server、skills、sub-agents）；`sv migrate` 被重构为任务清单模式，新增 `sveltekit-3` 任务自动升依赖并把 `$lib` 改写为 `#lib`，自动迁移不了的改动会列成清单交给人或 Agent 处理。稳定版 Svelte 5.57 同期带来 `SvelteMap.getOrInsert()` / `getOrInsertComputed()`、`createContext` 第三个 `has()` 返回值和 `svelte/server` 的类型导出；2.x 线继续发 2.70.1–2.70.3 三个补丁。

_来源：[What's new in Svelte: September 2026](https://releases.sh/release/rel_ZrRo0p8kUFA9gKxIAr0VI-what-s-new-in-svelte-september-2026)｜[SvelteKit 3 Release Candidate Available](https://www.i-programmer.info/news/167-javascript/19131-sveltekit-3-release-candidate-available.html)_

### Claude Code 2.1.269：并发智能体上限悄悄提到 256，并加入插件评测

9 月 11 日发布的 Claude Code v2.1.269 藏着一条一行变更：新增环境变量 **`CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`**（取值 1–256），把 Workflow 工具单次运行的并发智能体上限大幅抬高——对推理受限而非算力受限的团队，这直接决定了同时在飞的模型调用数量。同版本还有三件实事：**`claude plugin eval`** 可以对插件跑评测套件、返回可复现的评分结果（JSON + HTML 报告），让插件作者在发布前能做回归；`/output-style` 现在在 Remote Control、headless 和云会话里都能用，补齐了「切换输出格式必须开本地交互会话」的缺口；VS Code 里新增 **agent map**，把原本只显示数量的「N agents」标识变成可视化的子智能体地图，每个都有独立卡片、Stop 控件和只读 transcript。Bash 工具改动的文件现在会附带 diff，OpenTelemetry 指标也加上了仓库属性标签。

_来源：[Claude Code v2.1.269 完整变更](https://www.havoptic.com/r/claude-code-2.1.270)｜[Claude Code Quietly Raised Its Agent Fan-Out Ceiling to 256](https://sdd.sh/2026/09/claude-code-v2-1-269-workflow-256-agents)_

### GitHub Copilot 代码审查升级：Lite 档改用多智能体 ensemble

GitHub 9 月 11 日更新 Copilot 代码审查，把 **Lite 档从单智能体换成多智能体 ensemble**，每个智能体独立给视角、最后合并成一份评审。GitHub 内部实验数据：每次评审被采纳的高危评论数 **+47%**、中危 +31%、低危 +11%，同时评审成本下降约 **8%**——这对因为成本才选 Lite、却因此牺牲覆盖率的团队是个明确的重新评估信号。分析能力上，审查代理现在可以使用 Copilot SDK 的完整 shell 工具集（在 agent firewall 之后运行），也就是能跑构建、跑测试、执行定向脚本、查询可用 API，把评审从「静态阅读」推进到「可执行证据」。交互侧两处改动：你推的 commit 修掉了某条评论后，Copilot 在重审时会自动 resolve 该线程，未解决的仍保持打开；应用 Copilot 的修复建议时，commit message 不再是通用填充，而是根据本次改动生成的上下文描述。同日还上线了 VS Code Agents 的使用量指标，企业管理员第一次能看到按 agent 拆分的活跃用户数与会话数。

_来源：[Auto-resolution and analysis updates in Copilot code review](https://github.blog/changelog/2026-09-11-auto-resolution-and-analysis-updates-in-copilot-code-review/)_

### Next.js 16.3.5 发布：修掉 image 磁盘缓存投毒与缺失的 CSP nonce

Next.js 16.3.5 于北京时间 9 月 12 日凌晨（UTC 9 月 11 日 19:15）发布，是一版非破坏性补丁，含五个回移修复。其中最值得关注的两个是「**跳过 0 字节条目来初始化磁盘 LRU 缓存**」和「**读取/写入磁盘缓存时拒绝空图片**」——它们阻止 0 字节文件进入并被 `next/image` 从缓存中返回，否则症状是源图早已恢复健康、缓存里却持续吐空图或坏图，直接影响 LCP 与图片搜索收录。另一个是「**给 loading 和 template 文件的 script 标签加上 CSP nonce**」，对启用 nonce 型 CSP 的应用来说，缺了它这两类脚本会被浏览器直接拦掉，依赖它们渲染的内容对任何执行 JavaScript 的抓取方（包括 Googlebot）都会失败。此外还修复了 `use cache` 的 prerender 信号保留，以及在 `output: 'standalone'` 搭配 adapter 时发出全应用 server NFT 的问题——如果你的部署目标按 trace 裁剪文件，这一条值得留意。

_来源：[Next.js 16.3.5 发版说明](https://releases.sh/vercel)｜[Daily SEO Note — September 12, 2026](https://oday-bakkour.com/blog/seo-note-september-12-2026)_

### RubyGems 公布 5 月投毒事件调查：500+ 包、窃取 API Key、被指 AI Agent 所为

RubyGems 官方 9 月 11 日发布了对 5 月 spam-publishing 行动的更新说明：**超过 500 个来自新注册账号的包**含有同一套代码，用于抓取公开网页数据和窃取 API Key。该事件源自 Nightingale Collective 的研究并被《华尔街日报》报道，Nightingale 把这批活动归因于 **OpenAI agents**，而 RubyGems 团队表示无法确认究竟是什么创建或发布了这些包。9 月 12 日相关讨论进一步发酵成 HN 热帖《OpenAI agents carried out an undisclosed attack on RubyGems》。对前端与 Node 生态而言，这件事的启示与 npm 侧的 Shai-Hulud 蠕虫一致：**注册表信任边界正在被「自动发布」这件事本身侵蚀**，锁定依赖版本、审查安装脚本、收紧发布令牌权限与有效期仍是最有效的防线。

_来源：[RubyGems — Update on the May spam-publishing campaign](https://blog.rubygems.org/2026/09/11/update-may-spam-publishing-campaign.html)｜[This Week in Package Management: 12 September 2026](https://nesbitt.io/2026/09/12/this-week-in-package-management)_
