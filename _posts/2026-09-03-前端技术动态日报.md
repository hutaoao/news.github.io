9 月 3 日这天，前端圈的重头戏在工具链和浏览器安全两端：字节跳动 Web Infra 的 Rslib 终于发布 1.0，Google 紧急推送 Chrome 152 补丁修一个已在野外被利用的 V8 类型混淆漏洞。同时 OpenAI 的 GPT-6 Astra 把「建网站 + 自己跑前端测试」做成了官方演示案例，值得前端同学认真看一眼。

### Rslib 1.0 正式发布：字节 Web Infra 的库构建工具结束 0.x 阶段

基于 Rsbuild 的 JavaScript 库开发工具 Rslib 发布 1.0，从 0.7 以来累计迭代 16 个 minor 版本后承诺遵循 SemVer。官方基准显示，在包含 1 万个 React 组件的项目中，无缓存构建耗时从 1.212s 降到 0.918s（-24.3%），有缓存构建从 1.125s 降到 0.487s（-56.7%），Gzip 前产物体积从 7.64 MiB 降到 5.19 MiB（-32.2%）。类型生成支持 TS 7（tsgo）与 Isolated Declarations，在 Rsbuild 仓库上分别把 9.7s 压到 4.1s 和 2.3s。此外还支持构建 Module Federation 产物、React/Vue/Svelte/Solid 组件库，以及 `create-rslib` 直接安装面向 Coding Agent 的 Skills。1.0 含不兼容变更，官方提供了从 0.x 升级、以及从 tsc/tsup 迁移的指南。

_来源：[稀土掘金 - Rslib 1.0 正式发布](https://juejin.cn/post/7681133923887824948) ｜ [官方博客 Announcing Rslib 1.0](https://lib.rsbuild.dev/blog/v1-0)_

### Chrome 152 紧急安全更新：V8 类型混淆 CVE-2026-85046 已在野利用

Google 于 9 月 3 日推送桌面版 Chrome 稳定通道更新，Windows/macOS 为 152.0.7977.82/.83、Linux 为 152.0.7977.82，共修复 12 个漏洞。其中 CVE-2026-85046 是 V8 引擎的类型混淆漏洞，由 Salvatore Gulizia 于 8 月 4 日报告，Google 明确表示已知存在野外利用，这也是本次唯一被确认在野利用的条目。同批次还包含 V8 竞态（CVE-2026-85045）、Compositing 释放后重用（CVE-2026-85048）、Network 清理不彻底（CVE-2026-85043）等 10 个 High 级问题。距离上一轮 9 月 1 日的安全更新仅隔两天，桌面端建议尽快核对 `chrome://version`；Android 端本轮未包含在内。

_来源：[CVE 记录 CVE-2026-85043](https://www.cve.org/CVERecord?id=CVE-2026-85043) ｜ [Chrome Releases - Stable Channel Update for Desktop](https://chromereleases.googleblog.com/2026/09/stable-channel-update-for-desktop_01882797386.html)_

### HN 榜首：《浏览器的主线程很昂贵》

kciter 的长文当日登上 Hacker News 榜首。文章把前端性能优化重新框定为「对主线程这一稀缺资源的分配问题」，并给出系统的方法论：留在主线程内做拆分（splitting）、批处理（batching）、优先级（prioritizing）、延迟（deferring），或把工作移出主线程（交给合成器线程的 transform/opacity、Web Worker、Transferable 零拷贝）。文中援引了几个具体量级——60Hz 屏幕每帧预算约 16.6ms 但可用仅约 10ms，120Hz 设备减半；长任务阈值为 50ms；4000 粒子的逐帧距离计算约 1600 万次会直接爆掉帧预算。核心结论是：优化的最大收益往往来自「取消工作」而不是「加速工作」。

_来源：[Hacker News Daily - 2026-09-03](https://daemonology.net/hn-daily/2026-09-03.html) ｜ [原文 kciter.so](https://kciter.so/posts/the-expensive-main-thread/en/)_

### Claude Code 2.1.260：全屏 diff 面板与提示缓存未命中诊断

Anthropic 在 9 月 3 日发布了 Claude Code 2.1.260（距上一版仅一天），共 66 项变更：8 项新增、9 项改进、37 项修复。最受关注的是全屏模式下并排显示的 diff 面板，可实时查看 Claude 改动产生的未提交变更，用 `/diff` 切换；`/cost` 与状态栏的 `prompt_cache` 字段现在会给出提示缓存未命中的可能原因（工具定义或系统提示变化、空闲超过 TTL）。安全侧修掉了几个实打实的问题：路径含括号的 Edit/Write/Read 权限规则会被 Bash 沙箱丢弃、导致「只读」目录实际可写；某条无法编译的 deny 规则会让所有文件编辑失败；zsh 中藏在 `REPORTTIME` 类赋值里的命令替换会被自动放行。此外还修了 Bedrock 企业根证书、macOS 沙箱隐藏用户 git config 等问题。

_来源：[Claude Updates - v2.1.260](https://www.claudeupdates.dev/version/2.1.260) ｜ [Havoptic - Claude Code v2.1.260](https://www.havoptic.com/r/claude-code-2.1.260)_

### OpenAI 发布 GPT-6 Astra：官方演示里包含「建网站并自己跑前端测试」

OpenAI 于 9 月 3 日正式发布 GPT-6 Astra，Greg Brockman 用「欢迎来到 AGI 时代」收尾。与前代相比，Astra 主打连续执行完整任务：跨浏览器、代码与专业软件操作，遇到问题后继续修正。官方演示场景中明确包含「创建网站并进行前端测试」。编码相关基准上，Astra 在 Terminal-Bench 4.0 得 57.9%（GPT-5.6 Sol 为 37.3%，Claude Fable 5.1 为 55.8%），DeepSWE v1.1 得 74.1%；OSWorld 2.0 离线子集得 72.6%，单项任务平均耗时从约 75 分钟降至 40 分钟。价格方面标准 API 为每百万输入 token 10 美元、输出 50 美元，是 GPT-5.6 Sol 的 2.5 倍。目前先向少量机构开放，随后几天覆盖 ChatGPT Plus/Pro/Business/Enterprise 及 API、AWS Bedrock。

### 鸿蒙 7：沉浸光感新增生效约束，targetSdkVersion ≥ 26.0.0 需自查适配

华为开发者官网 9 月 3 日更新 OS 平台行为变更说明，为沉浸光感组件新增生效范围约束，理由是「确保性能和功耗体验最优」。变更前，支持开启沉浸光感的组件开启后即可生效；变更后，只有弹窗类组件（AlertDialog、ActionSheet、CustomDialog、各类 PickerDialog 等）、弹窗类接口（PromptAction、菜单控制、半模态转场等）以及按钮与选择类组件（Slider、Toggle、Select）仍可在页面全部区域生效，其他组件仅在 Navigation / NavDestination 标题栏、或 `barPosition` 为 `BarPosition.End` 的底部 TabBar 中生效。由于涉及接口为 26.0.0 Beta 新增，只有 `targetSdkVersion` 大于等于 26.0.0 的应用受影响，鸿蒙开发者需要排查 `systemMaterial` 的使用位置。

### Flutter 3.47.2 发布：DDS 启动失败不再崩溃，修复一批平台问题

Flutter 于 9 月 3 日发布 3.47.2。主要修复包括：在 Web 端 DDS 启动期间 WebSocket 升级失败时优雅处理 `DartDevelopmentServiceException` 而非崩溃；修复 Linux 上处理触摸事件导致的内存泄漏；修复 Linux 屏幕阅读器无法朗读 header 元素；修复 Windows 上使用外部纹理时引擎绘制可能崩溃；Flutter 工具在自定义设备 ping 超时时不再崩溃。另有若干工程侧改进，如 `analysis_options.yaml` 中 flow-style `exclude:` 序列的转换处理、只对真实存在的平台目录做 analysis 排除、桌面端把 `--build-name`/`--build-number` 透传到构建管线，并更新 libpng 以修复安全漏洞。启用 SwiftPM 的 iOS/macOS 项目在 Xcode 27 下仍可能构建失败。

### npm 供应链：xmldom 与 link-preview-js 两个 CVE 同日被 GitHub 复核

9 月 2 日经 GitHub 复核、9 月 3 日进入每日审计视野的两个前端常用包漏洞值得关注。CVE-2026-83610 是 `@xmldom/xmldom` 中通过 `EntityReference` 的 `nodeName` 实现的 XML 注入，需升级到 0.9.12（0.8 线为 0.8.15）；未加作用域的旧 `xmldom` 包（≤ 0.6.0）无修复版本，只能移除。CVE-2026-61704 是 `link-preview-js` 的 OG 预览抓取器中的 DNS rebinding SSRF，需升级到 4.0.4。两者都是非破坏性升级，但 xmldom 的修复新增了创建期校验，会拒绝非法 XML 名称——原本静默产生畸形节点名的生成器现在会抛错。

### Cloudflare Images 支持文本栅格化与直接设置响应头

Cloudflare 于 9 月 2 日上线、9 月 3 日进入审计视野：Images binding 新增 `.text()` 方法，可指定字体、字号、颜色把文本栅格化；`cf.image` 的 draw 数组支持 `text` 键做叠加；`.response()` 现在可以直接接收 `headers` 选项，不必重建整个 Response 对象。组合起来的实际价值是——边缘生成的 OG 图不再需要无头浏览器：模板图 + 标题文本在边缘合成，同时带上正确的 `Cache-Control`，避免社交卡片接口因为每次抓取都重新生成而成为全站最慢的路由。该功能为增量、非破坏性，Images binding 上已全面可用。
