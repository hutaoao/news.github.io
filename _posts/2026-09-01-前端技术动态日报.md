开学日这天前端圈不太平静：两条高危供应链/安全通告同时落地，AI 编程工具集体在 9 月 1 日这个节点切换模型与计费，浏览器端的 WebGPU 底层也有重量级开源发布。以下是今天的完整盘点。

### npm 供应链投毒：@7nohe/openapi-react-query-codegen 一次发出 10 个「带有效 Provenance」的恶意版本

周下载量约 15 万的 TanStack Query 代码生成包 `@7nohe/openapi-react-query-codegen` 遭劫持，攻击者在 8 月 28 日约 20 分钟内连续发布 10 个恶意版本，覆盖了所有仍在维护的版本线。最值得警惕的是：这些版本都带有**合法有效的 npm Provenance 来源证明**，看起来完全像是由正规 GitHub Actions 流程发布的 —— 因为攻击者正是利用了「PR 评论可触发发布工作流」且未校验评论者身份的漏洞，让工作流 checkout 了 fork 上的代码并用 OIDC 受信身份发布。恶意代码在 `npm install` 时通过构建配置与 pre-install 命令执行，会扫描项目文件、进程内存、云元数据服务和 CI 变量中的凭证，并写入攻击者创建的公开 GitHub 仓库；还会篡改 GitHub Actions 工作流、往 AI 编码助手配置里塞后台命令，并通过可SSH 主机传播。Socket 与 JFrog 将其定性为「Mini Shai-Hulud / Trinitite」系列。处置建议：先隔离机器与 runner 并保留证据，再轮换 npm / GitHub / 云 / CI 凭证，从干净镜像重建环境。

_来源：[Socket.dev](https://socket.dev/blog/openapi-react-query-codegen-npm-compromise) / [JFrog 安全研究](https://research.jfrog.com/post/shai-hulud-trinitite/)_

### Vitest 修复路径穿越漏洞 CVE-2026-84373，可读取项目根目录外任意文件

CVE 记录于 9 月 1 日更新：Vitest 从 2.1.0 到 4.1.11 之前、以及 5.0.0-rc.2 之前的版本，`mockerPlugin` 与独立导出的 `interceptorPlugin` 会在 Vite **未鉴权的 HMR WebSocket** 上注册 `vitest:interceptor:register` 处理器，却没有对 `event.redirect` 做 `server.fs.allow` / `server.fs.deny` 校验。能访问到暴露的开发服务器的远程客户端，可以提交保留 `..` 段的不透明 URL scheme，让 `join(server.config.root, redirectUrl.pathname)` 解析到项目根之外，插件的 load 钩子随后把文件内容当作模块源码返回，从而泄露本地文件。CVSS 3.1 评分 5.9（MEDIUM）。已在 **4.1.11 和 5.0.0-rc.2** 修复，浏览器模式默认走 token 鉴权 RPC，不受未授权远程影响。开着 dev server 到公网或共享网络的团队请尽快升级。

_来源：[CVE-2026-84373](https://www.cve.org/CVERecord?id=CVE-2026-84373) / [GHSA-82fw-gwwq-j7x9](https://github.com/vitest-dev/vitest/security/advisories/GHSA-82fw-gwwq-j7x9)_

9 月 1 日由 The Hacker News 扩散的这起攻击，把招聘流程本身变成了投递通道：受害者收到托管在 Amazon S3 上的 `Front-Technical-Challenge.zip`，解压后是一个叫 TaskFlow 的项目，README 要求「短时间内修复前端 bug」并明确提示不要改动服务端部分 —— 而恶意代码就藏在 `server.js` 里。该文件第一行 import 了一个名为 `colorized_terminal@2.1.0` 的投毒 npm 包，它并未发布到 registry，而是直接夹带在归档的 `node_modules` 目录里。执行后会从隐藏缓存路径拉起 NodeRabbit RAT，跨 Windows / Linux / macOS 持久化。README 还特意劝阻使用 AI 助手，目的很明确：减少执行前的独立审查。

### Chrome 网上应用商店完成 Manifest V2 清退，uBlock Origin 正式下架

谷歌在 8 月 31 日执行了扩展路线图的最后一步，删除商店中所有剩余的 MV2 扩展；9 月 1 日起，包括 Edge、Brave、Vivaldi、Opera 在内的整个 Chromium 生态都无法再通过商店搜索或安装 MV2 扩展。已安装在 Chrome 138 及更早版本上的 MV2 扩展可继续运行，但再也收不到更新，卸载后也无法重新安装。最具代表性的受害者是 uBlock Origin —— 作者 Raymond Hill 上周发布的 1.74 已是「预计能进商店的最后一个稳定版」。Brave 选择自建后端托管 uBO、AdGuard、uMatrix、NoScript 四款；Firefox 155 继续完整支持 MV2。

_来源：[CyberInsider](https://cyberinsider.com/google-removes-ublock-origin-from-chrome-web-store-in-final-manifest-v2-purge/) / [Chrome Unboxed](https://chromeunboxed.com/manifest-v2-is-officially-dead-as-the-chrome-web-store-permanently-purges-legacy-extensions/)_

### Chrome 152 正式版：一次修 327 个漏洞，同时带来一批新的 Web API

Chrome 152 自 8 月 25 日起渐进推送（152.0.7977.64/.65），安全修复总数达 **327 个，其中 10 个为 critical**（8 个 use-after-free，涉及 ANGLE、Aura、Chromecast、Views、Safe Browsing）。开发者侧的新能力包括：`CSSPseudoElement` 扩展到 `::backdrop`、`::scroll-marker`、`::view-transition`；新的 **CPU Performance API**；`Connection-Allowlists` HTTP 头用于收紧页面可用网络请求；CSS `alpha()` 函数（CSS Color 5 相对 alpha）；标准化并重命名 `app-region` 的 `window-drag` 属性；全局 `autocorrect` HTML 属性；以及用于表单控件内文本区间操作的 `OpaqueRange` API。

### Hugging Face 发布 @huggingface/kernels：207 个 WebGPU 内核 + Fleet 众测套件

Hugging Face WebAI 团队于 9 月 1 日放出浏览器端推理「第一层」：`@huggingface/kernels` 是一个极简 JS 加载库，配合 Hub 上的首批 **207 个 WebGPU 内核**（Apache-2.0）。亮点不在数量而在工程化 —— 每个内核都是一个完整版本化包，包含 `manifest.json`（算子契约）、`metadata.json`（来源）、`test.json`（正确性用例）、`bench.json`（基准用例）以及参数化的 `*.wgsl.jinja` 着色器模板。同步推出的 **Fleet** 是跑在浏览器里的 GPU 基准与验证套件，在征得同意后把私有证据回传，帮助团队发现实验室覆盖不到的设备上的失败与病态慢速案例。官方基准显示，在 Apple M4 上 809 个可比用例中，几何平均比 ORT WebGPU 快 **2.57×**（中位数 1.90×，629 胜 / 176 负 / 4 平）。

_来源：[Hugging Face Blog](https://huggingface.co/blog/webgpu-kernels)_
