## 前端技术动态日报

本日报整合 2026 年 8 月 12 日当周及前几日的核心前端技术动态，涵盖 CSS 年度调查、运行时、构建工具、代码质量等多个维度。

### State of CSS 2026 年度调查正式发布：Anchor Positioning 登顶最爱新特性

Devographics 团队于 2026 年 8 月发布了 State of CSS 2026 年度调查，收到了来自全球 4,902 位开发者的反馈。调查结果显示：**Anchor Positioning（锚点定位）**成为开发者最爱的新 CSS 功能第一名，其次是 **`:has()` 选择器**和 **@container size queries（容器查询）**。同时，Anchor Positioning 也因浏览器支持限制而成为开发者「最想用却不敢用」的特性榜首，View Transition API 和 `if()` 条件函数紧随其后。在 CSS 痛点方面，布局问题（Layout issues）、浏览器兼容性和动画性能问题排名前列。整体来看，CSS 正在以前所未有的速度引入新特性，开发者对 Cascade Layers、`@scope`、Scroll-driven Animations 等特性的使用率也在持续攀升。

_来源：[State of CSS 2026](https://2026.stateofcss.com/en-US/)_

### pnpm 11.20.0 修复高危供应链风险：多 registry 包替换漏洞

8 月 3 日，pnpm 发布 11.20.0 版本，修复了 11.1.0~11.19.x 版本中存在的**高危供应链安全漏洞**——当同一项目使用多个 registry 且安装同名同版本包时，锁文件可能将不同来源的 tarball 错误合并，导致包替换风险。新版本在锁文件键中加入了 registry 身份标识，下次非 frozen 安装会自动重写受影响条目。团队还需注意保留所有已引用的 namedRegistries 别名，避免更新后出现 `ERR_PNPM_MISSING_NAMED_REGISTRY` 错误。使用私有镜像、GitHub Packages 或多 registry 的项目建议立即升级并提交锁文件变更。

_来源：[pnpm 11.20 Release Notes](https://pnpm.io/blog/releases/11.20)_

### Node.js 三版本同步更新：24.19 LTS、26.6 与 26.7 Current 同周发布

8 月 3 日至 5 日，Node.js 罕见地在一周内同步发布了三个版本：**24.19.0 LTS**（长期支持版）补充了 `blob.textStream` 和稳定的 `stream.compose` API；**26.6.0** 与 **26.7.0 Current** 则新增了 Perfetto 追踪支持、NSS 根证书更新和模块钩子释放能力，测试工具也获得 `context.log()` 和覆盖率全量包含等改进。24.x 用户可优先评估兼容性并规划升级；26.x 用户应以 26.7.0 为最新基线重新跑测试和诊断链路。

_来源：[Node.js v24.19.0](https://nodejs.org/en/blog/release/v24.19.0) / [v26.6.0](https://nodejs.org/en/blog/release/v26.6.0) / [v26.7.0](https://nodejs.org/en/blog/release/v26.7.0)_

### TanStack Table V9 稳定版发布：插件化架构重构，按需引用更轻量

8 月 4 日，TanStack Table V9 正式发布稳定版，这是该库自发布以来最重要的架构升级之一。新版本引入了**完全插件化的架构设计**，允许开发者按需引用功能而非全量导入，大幅减少了最终产物的体积。核心功能包括：更灵活的列定义与虚拟化支持、更强的类型推断、以及与 React、Vue、Solid、Svelte 等主流框架的无缝集成。对于已有项目，V9 提供了从 V8 的平滑迁移路径，建议查看官方迁移指南后逐步升级。

_来源：[TanStack Table V9 Release](https://tanstack.com/blog/table-v9-release)_

### Vite 8.2.1 紧急修复：共享插件与 chunk import map 回归问题

8 月 6 日发布的 Vite 8.2.1 是一个紧急补丁版本，修复了三大问题：① 当 `sharedPlugins: true` 时客户端 chunk import map 失效；② bundled dev 模式下客户端脚本插入顺序不正确；③ CSS 压缩时重复执行 Lightning CSS visitor。此外还修正了库模式入口解析时意外修改用户配置、以及随机端口和纯 CSS chunk 的处理逻辑。使用共享插件、多入口懒加载或嵌入式开发服务器的项目可直接替换为此补丁版本，并在升级后复测生产构建与动态导入。

_来源：[Vite 8.2.1 Changelog](https://github.com/vitejs/vite/blob/main/packages/vite/CHANGELOG.md#821-2026-08-06)_

### Rolldown 1.2.2 & 1.2.3 连发：动态入口优化与 watch 修复

8 月 3 日发布的 Rolldown 1.2.2 新增了在动态入口中内联共享依赖的能力，并让插件时间统计覆盖用户回调；8 月 5 日的 1.2.3 则修复了 watch 批次注册失败、已废弃的 `watch.notify` 暴露及部分收尾阶段的内存分配问题。由于动态 import 的行为变化，升级后可能影响 chunk 组成和产物体积。依赖自定义插件或 watch API 的工具链团队应在升级后核对 chunk 图、热更新和插件钩子的行为一致性。

_来源：[Rolldown 1.2.2](https://github.com/rolldown/rolldown/releases/tag/v1.2.2) / [1.2.3](https://github.com/rolldown/rolldown/releases/tag/v1.2.3)_

### Oxlint 1.77.0 支持 GitHub 文件行号注释：Oxfmt 0.62.0 完善 YAML 格式化

8 月 3 日，Oxc 工具链同步更新：**Oxlint 1.77.0** 新增支持 `file:line:column` 形式的 GitHub Actions 代码注释，并改善了 `.gitignore` 处理、JavaScript 插件名识别和多条规则的处理精度；同批发布的 **Oxfmt 0.62.0** 新增了 Vue 中 TypeScript JSX 语法的格式支持，在 check 模式下展示颜色差异，并启用了全新的 YAML 格式化器。需要注意的是，YAML 输出格式的变化可能与已有的格式化基线产生差异，建议固定版本后对比变更内容。

_来源：[Oxc v1.77.0 Release](https://github.com/oxc-project/oxc/releases/tag/apps_v1.77.0)_

### ESLint 10.8.1 修复自动修复边界问题，v9 正式结束生命周期

8 月 7 日，ESLint 发布了 10.8.1 版本，修复了 `no-unused-labels` 与 `no-unused-vars` 自动修复时可能错误插入自动分号的问题，同时降低了 `getter-return`、`accessor-pairs`、`id-denylist` 和 `id-match` 规则的误报率。值得注意的是，**ESLint v9 已于 8 月 6 日正式结束维护**，仍在使用 v9 的项目将不再收到任何安全更新和 bug 修复。建议所有团队将 ESLint 升级到 v10 最新补丁版本，并在升级后运行 `--fix-dry-run` 审阅所有自动修复的变更。

_来源：[ESLint v10.8.1 Release](https://eslint.org/blog/2026/08/eslint-v10.8.1-released/)_

### Ant Design 6.5.4 发布：修复表格选择与 RangePicker 交互问题

8 月 7 日，Ant Design 发布 6.5.4 版本，重点修复了 Table 组件的 checkbox 选择在特定场景下的交互异常，以及 DatePicker.RangePicker 在切换月份时的语义行为问题。新版本还包含了多项内部稳定性改进，尚未升级到 Ant Design 6.x 的项目建议评估升级路径，已在 6.x 的项目可直接更新到此补丁版本。

_来源：[Ant Design 6.5.4 Release](https://github.com/ant-design/ant-design/releases/tag/6.5.4)_

### Web Weekly #197：CSS `closedby` 属性、容器计时 API 与 `infinity` 妙用

Web Weekly 最新一期（#197）聚焦了多项 CSS 与 Web Platform 新动态。值得关注的有：**`closedby` 属性**（用于声明元素间的互斥关系，让浏览器或辅助技术自动处理展开/收起逻辑）正处于标准化推进中；Harry 在博客中详细解析了新的 **Container Timing API**（`containertiming` 属性，Chrome 正在进行 Origin Trial），它允许开发者精确测量组件级别的渲染性能；此外，Adam 分享了 **CSS `infinity`** 的创意用法——可以用它来超越最大 `z-index`（2147483647）实现层叠覆盖。同期 Lea Verou 也发文呼吁重视 polyfill 的价值，认为在浏览器特性快速迭代的时代，polyfill 仍是弥合兼容性差距的关键手段。

_来源：[Web Weekly #197](https://webweekly.email/archive/web-weekly-197/) / [Container Timing API 解析](https://csswizardry.com/2026/07/meaasuring-component-performance-with-the-container-timing-api/)_
