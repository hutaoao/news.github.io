9 月 6 日这天，四家 AI 编程工具在同一天发了版本，而且没有一家是在宣布新模型——全都在补长期运行会话与多智能体场景的可靠性。这恰好印证了本周的一个判断：前沿模型已经在各助手之间按天对齐，真正还在竞争的变成了「中断的命令能不能正确恢复」「失败的子代理能不能续跑」「长会话能不能导出审计」这类工程细节。

### Claude Code 2.1.263：纯修复版，专治后台会话与多智能体的「幽灵状态」

Anthropic 于 9 月 6 日发布 Claude Code 2.1.263，是一次纯粹的可靠性补丁，全部针对后台会话与动态工作流。具体修的问题都很具体：命令被中途打断后仍显示为已完成的「Ran 1 shell command」且毫无被截断的痕迹；在动态工作流中按 ← 或执行 `/background` 会静默重启已完成的子代理（现在会先询问并说明会重启多少个）；在 worker 仍在启动时用 `claude agents` 打开刚创建的会话，会因竞态报「stopped while the respawn was in flight」并被杀掉；`claude agents` 会重复列出已后台化的命名会话；后台保留清理任务会误删用户自己在 `.claude/worktrees/` 下创建的 git worktree。此外，auto 模式的安全检查超时时间现在随 prompt 体积伸缩，避免超大会话里工具调用被误判为「temporarily unavailable」。底层还调整了子代理默认后台化的引导、持续运行模式在只剩等待时干净结束回合、以及会话压缩区分「全量摘要」与「仅近期摘要」。另外注意：SDK 兼容矩阵已刷新，0.3.221 / 0.3.222 两个 wrapper 版本被移出测试列表，锁版本低于 0.3.223 的团队升级前需重新核对。

### GitHub Copilot CLI v1.0.83：Windows 任务栏常驻 + 支持自定义 agent

GitHub 的 Copilot CLI 发布 v1.0.83，继续把自己从「一次性终端命令」往「常驻桌面工具」方向推。新版本会把活跃会话显示在 Windows 任务栏上并给出实时状态更新，长跑的 agent 任务不再消失在某个后台标签页里；同时新增自定义 agent 支持，开发者可以定义并在多个会话间复用自己的 agent。这与 VS Code 1.135（8 月 26 日发布）引入的 Agent Host Protocol 是同一条线——该协议让多个 VS Code 窗口连接到同一个 agent 会话，并把在 Copilot / Claude Code 里启动的外部会话直接呈现在 VS Code 的会话列表中。

_来源：[Oday Bakkour - AI Coding Roundup September 6, 2026](https://oday-bakkour.com/blog/ai-coding-roundup-september-6-2026) ｜ [GitHub Copilot CLI releases](https://github.com/github/copilot-cli/releases)_

### VS Code 1.135 的 /rubber-duck：刻意用「另一族模型」来审查你的 agent

VS Code 1.135 里的实验性 `/rubber-duck` 命令本周持续在社区发酵。它的机制值得单独说：把当前计划、diff 和测试交给**另一个模型家族**的模型来批评——你的主会话跑 Claude，评审者就是 GPT-5.4，反之亦然。理由是自审的失敗模式：产生盲点的权重和检查盲点的权重是同一套，模型写代码时没想到并发写的问题，审代码时同样想不到。它是只读的批评者，不能编辑，输出按 blocking / non-blocking / suggestions 三级分类（这个分级本身值得借鉴到自己写的 review 子代理上）。Copilot 会在四个时机自动触发：起草计划后、复杂实现后、写完测试但还没跑时，以及 agent 陷入循环时——最后一个最值，因为循环正是主模型「对自己的输出已经没辙了」的最强信号。注意它不是免费的：每次自动调用都是一次完整的模型回合，按 premium 用量计费。

### Codex CLI：远程插件市场、vim 撤销重做、更早的用量预警

OpenAI 的 Codex CLI 本周也有一批更新，超出 GPT-6 Astra 的接入范畴。vim 模式现在支持撤销与重做（`u` 与 Ctrl+R），并能在分组编辑步骤之间保留完整草稿（包括粘贴内容与附件）。插件 CLI 可以从远程市场列出、安装和移除插件，目录条目会显示来源、版本、安装策略与认证策略。新增 `tui.auto_recap = false` 设置，可关闭自动 recap 但保留手动 `/recap`。Plus 与 Team 套餐在约五小时额度剩余不足一半时会更早收到用量预警。

_来源：[Oday Bakkour - AI Coding Roundup September 6, 2026](https://oday-bakkour.com/blog/ai-coding-roundup-september-6-2026) ｜ [Codex CLI changelog](https://learn.chatgpt.com/docs/changelog)_

### OpenCode：子代理失败可恢复，会话可整体导出 JSON

SST 的 OpenCode 本次主打「让失败可恢复而不是静默」。失败的子代理工具调用现在会带一个可恢复的 `task_id` 而不是返回空结果，掉线的子代理可以接着跑而不用从头开始。Provider 超时处理也被修了：默认 header 与流式 chunk 超时都设为 5 分钟，以适应慢启动的模型；以 `network_error` 结尾的响应现在会自动重试。此外用户可以直接从 UI 把完整会话记录导出为 JSON，便于审计与复盘。

_来源：[Oday Bakkour - AI Coding Roundup September 6, 2026](https://oday-bakkour.com/blog/ai-coding-roundup-september-6-2026) ｜ [OpenCode changelog](https://opencode.ai/changelog)_

### Better Auth v1.7.3：恢复 v1.6 schema 兼容，默认开启密码泄露检查

Better Auth 于 9 月 6 日发布 v1.7.3。几个改动对前端接入方影响直接：恢复了 v1.6 的 schema 兼容性（此前升级造成的数据结构差异是主要摩擦点）、默认开启 schema 校验、新增 `isPasswordCompromised`（接 HIBP 做密码泄露检查）、新增 Cloudflare 社交登录的 PKCE 支持，以及 OAuth 发现健壮性和 TOTP 的若干修复。这个项目目前 3 万 star、935 名贡献者，周更节奏稳定；配合 Auth.js/NextAuth 已进入维护模式、官方把新项目导向 Better Auth 的背景，它基本已经成为 TypeScript 生态自建鉴权的默认选项。

### 吴恩达发布 Coding Agent 技能图谱：五项能力 + 对超长自主运行的降温

9 月 6 日吴恩达发布《AI Engineering Skills Map: Using coding agents》，提出「规划—执行—部署—监控」三阶段工作流，并列出五项关键能力：引导工作流、赋予 agent 自主权、审查输出、定制环境、理解底层原理。值得注意的是他同时泼了盆冷水——超长自主运行的实际效用常被夸大。结合近期 Claude Code 连续修后台会话可靠性、OpenCode 让子代理失败可恢复这些动作，行业对「agent 长时间自主跑」的态度正在从兴奋转向工程化的现实主义。

_来源：[腾讯新闻 - AI编程工具最新动态](https://new.qq.com/rain/a/20260907A00YD600?refer=cp_1009)_

### 值得一看：Spotify 工程师称内部工具让 Claude Code token 用量降 90%

Spotify 工程师在官方工程博客分享了实测：用内部工具 Portal 跑 Claude Code，token 用量下降 90%。需要标注的是这是个人使用体验而非 Spotify 官宣的基准测试，也没有提及开源。不过在 Claude Code 2.1.260 刚加入提示缓存未命中诊断（`/cost` 与状态栏会给出可能原因：工具定义或系统提示变化、空闲超过 TTL）的背景下，这类「怎么把上下文成本压下来」的实践值得一看——先搞清楚它缓存了什么、是否适配你的工作流，再决定是否照搬。
