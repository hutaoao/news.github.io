今天的主角是包管理器：pnpm 12.4 让一个 workspace 同时管住 npm、Cargo 和 Python 三套依赖，这是「包管理器」这个概念第一次真正跨语言。安全线上 Verdaccio 修掉一个会把你 uplink 认证头发给陌生主机的洞，GitHub Actions 也补上了一条缓存投毒的通路。

### pnpm 12.4 发布：一个 workspace 同时管理 npm、Cargo 和 Python 依赖

pnpm 12.4 最受关注的能力是**跨生态依赖管理**——在 `pnpm-workspace.yaml` 里启用 Cargo 与 Python 后，一次 `pnpm install` 就能同时处理三套技术栈，各自读自己的 manifest，共用 pnpm 的共享 store、认证和离线缓存。新增的 **`pnpm pipeline`** 命令用来声明 CI 风格的任务图，另外加了六个新架构的二进制。12.4.1 紧接着修掉在拒绝硬链接或 copy-on-write 克隆的文件系统上安装失败的问题，11.x 线则由 11.26 回移了 catalogs 中的 `workspace:` 范围、`remove`/`update` 的信任策略开关以及供 CI 使用的 `pnpm change check`。把三套生态收进同一个锁文件与缓存，对同时维护前端与 Python 服务的团队是个实打实的收益，但也意味着依赖审计的边界要重新划一次。

_来源：[pnpm 12.4 发布说明](https://pnpm.io/blog/releases/12.4)｜[This Week in Package Management: 12 September 2026](https://nesbitt.io/2026/09/12/this-week-in-package-management)_

### Claude Code 2.1.270：整个版本只修一条回归

Claude Code v2.1.270 于 9 月 12 日发布，changelog 里**只有一条**：「修复只读 git 命令在会话运行一段时间后意外索要权限（2.1.269 引入的回归）」。症状很讨厌——一切正常跑一小时后，`git status` 和 `git diff` 突然开始在一个本来干净的会话里请求批准，很容易被误诊为设置问题或权限缓存过期，因为它只在长会话里出现，而那正是你最不想重启排查的时刻。这条值得单独说，是因为它同时暴露了两件事：一是 Claude Code 的发版节奏已经到了 **1.1 天一个版本**（近一个月 29 个版本），回归与修复都在同一天落地；二是「只读命令不弹权限」对无人值守的长时程代理工作来说是硬需求，一旦失守，整个自动化链条就退回手动确认。

_来源：[Havoptic — Claude Code v2.1.270](https://www.havoptic.com/r/claude-code-2.1.270)｜[Claude AI Daily Brief — September 13, 2026](https://www.cadb.info/reports/claude-ai-daily-2026-09-13.html)_

### OpenAI Codex CLI 0.154.0 铺开：GPT-6-Astra 进模型选择器，新增实验性 worktree

Codex CLI 0.154.0 把 **GPT-6-Astra 放进模型选择器与 Amazon Bedrock 目录**，并加入**实验性 worktree 支持**——用 `--worktree` 启动或会话内 `/worktree` 为新建/分叉会话创建隔离的 git 检出，之后可浏览与恢复。这个特性的关键点在「分叉会话」：把一个已经走到半路的会话 fork 出去、让它在自己的检出里探索另一条路径，两边互不踩文件，这正是并行跑多个代理时最容易出事的环节。同版本还有几处实用改进：任务进行中可以用建议选项或自文本**内联回答提问**而不丢草稿，Windows 会话能共享后台 Codex server（带守护进程生命周期命令与托管更新），启动时不再在建立信任之前执行工作区控制的 helper，macOS 沙箱开始阻止终端输入注入。**破坏性变更一处**：已弃用的 `codex mcp-server` 入口点彻底移除，脚本、服务定义或编辑器集成里如果还引用它，升级前必须先替换。

_来源：[Codex CLI 0.154.0 changelog](https://developers.openai.com/codex/changelog)｜[Codex Just Made GPT-6 Astra Its Default](https://terminalblog.com/blog/codex-0-154-gpt6-astra-worktrees-windows-daemon)_

### Verdaccio 6.10.3 修复：不再把 uplink 的 Authorization 头送给无关主机

私有 npm 仓库 Verdaccio 发布 6.10.3，修掉一个实打实的凭证泄露：此前它会去抓取**客户端可控的 `dist.tarball` URL**，即使该主机不在配置的 uplink 列表里，也可能把一个 uplink 的 `Authorization` 头送出去。修复后的行为是本地发布的包直接返回 404，且跳过 off-uplink 的抓取。这类漏洞的可怕之处在于它不需要攻击者拿到任何权限——只要能让你的 Verdaccio 解析到一个指向自己的 tarball 地址，就能收到本该只属于内网仓库的凭证。跑自建 registry 的团队应优先升级，并顺手检查是否存在配置文件里的通配 uplink。

_来源：[Verdaccio v6.10.3 release](https://github.com/verdaccio/verdaccio/releases/tag/v6.10.3)_

### GitHub Actions 新增 cache-mode：从源头切断一条缓存投毒路径

GitHub Actions 加入了 workflow 与 job 级别的 **`cache-mode`** 设置，可选 `read`、`write`、`write-only`、`none`。意义在于：一个只需要恢复缓存的 job，现在可以被明确禁止写回缓存，从而切断「低权限任务污染高权限任务所用缓存」这条投毒链路。在 CI 权限模型里，缓存一直是个尴尬的共享状态——它跨 job、跨分支存在，却没有对应的权限语义。加上 `cache-mode` 之后，团队可以按「谁有资格写缓存」来重新划一遍 job 的权限边界，而不是靠约定俗成。

_来源：[Control GitHub Actions cache access with cache-mode](https://github.blog/changelog/2026-09-10-control-github-actions-cache-access-with-cache-mode/)_

### RubyGems / Bundler 4.1.0.beta1 与包管理生态的其他动作

RubyGems 与 Bundler 的 4.1.0.beta1 进入测试，带来**内容寻址的 gem 支持**、签名流程的 **ML-DSA 后量子签名**、可选的 OS 凭证存储（用于 gem 与 bundler 凭据），以及 `gem install`/`update`/`outdated` 上的 `--cooldown` 参数——用来避免刚发布的版本立刻被拉进构建。同期其他生态：Pixi 0.80.0 加入实验性 `conda-script` 支持（脚本头部注释声明 channel、依赖与入口，类似把 PEP 723 内联元数据扩展到所有 conda-forge 覆盖的语言）；uv 0.12.13 把 GraalPy 3.13.0 加进托管 Python 构建，并在能用 URL 片段里的哈希时跳过完整 wheel 下载；mise 2026.9.5 扩展了 macOS bootstrap；Terraform 1.17.0-beta1 支持 `required_providers` 里使用变量与 locals，Gradle 9.8.0 RC1 加入 Java 27 支持。对前端团队而言，`--cooldown` 和内容寻址这两条思路值得关注——它们都在回答同一个问题：**如何让「装依赖」这件事自带一点时间与内容的验证**。

### Cognition 把 Devin 升级成双模型协作：SWE 基准成本降 39%

Cognition 将 Devin 升级为「双模型协作」模式：**主模型（Claude Fable 5.1 或 GPT-6 Astra）负责规划，小模型 SWE-2 负责写代码**，在 SWE 基准上成本降低 **39%**、速度提升 **31%**。Artificial Analysis 也是第一次把多模型协作型编码 Agent 纳入 Coding Agent Index。这件事和同期 GitHub 的 HydraFusion、Cursor 的 Projects 指向同一个方向：**编码代理的竞争点已经从「选哪个模型」转向「怎么编排一段工作流」**，成本、质量、延迟成为联合优化目标，而不是各自单独拉满。对实际使用者来说，副作用是账单结构会变复杂——你不再为一个模型付费，而是为一次工作流里每一段草稿、评审、修订和升级付费。
