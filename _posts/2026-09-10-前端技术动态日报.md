今天最重的一条不是新版本，而是一次撤退：Shopify 官方宣布放弃 React Native、全面回归 Swift 与 Kotlin，理由是「编码智能体把重复实现的成本打下来了」。同一天 Vite 8.3.0 转正、Edge 153 的 Web 平台特性落地、Cognition 发布 SWE-2，前端的每一个层面都在被重新定价。

### Shopify 官宣弃用 React Native，全面回归 Swift 与 Kotlin

Shopify 工程博客 9 月 10 日发文，正式宣布将全部移动应用从 React Native 迁回原生。这是 2020 年「all-in React Native」决策的逆转，官方给出的理由很直接：2020 年选择 RN 的三个前提（不用重复造功能、开发者可跨栈、少追平台对齐）中，第一个已经被 LLM 消解——现在用 Swift 写一遍、再用 Kotlin 写一遍，不再等于「做两遍工」。他们从 2021 年就开始用 LLM 写软件，到 2025 年底模型能力已经强到让他们重新评估整个移动端技术栈。具体数据：Shop App 从 PoC 到双端原生上架只用了 **12 周**；Shopify 主 App（300+ 屏、含桌面小组件、Apple Watch、Siri 捷径）迁移正在进行，年内发布。为了防「slop」，他们自研了 **Helix** 系统：把每个屏幕拆成一串可分钟级评审的 checkpoint，每个 checkpoint 必须带测试、通过视觉对比、扛过两个对抗性代码审查者、拿到人类点头才能进入下一个，且所有评审反馈会被记住、让循环越跑越自主。另一个关键工程是**把业务逻辑与 UI 彻底解耦、能无头跑在桌面上并通过 CLI 暴露给智能体**，绕开「模拟器 + 无障碍树」这个慢得离谱的反馈瓶颈。开源库处置：React Native Skia 由 William Candillon 接手并在未来数月 fork 更名（Shopify 赞助到 2026 年底）；FlashList（周下载约 200 万）正在寻找长期 steward；Restyle 用户较少，将归档。

_来源：[Native is now the future of mobile at Shopify](https://shopify.engineering/back-to-native)_

### Vite 8.3.0 正式发布，同步推出 create-vite 9.2.1

Vite 8.3.0 于 9 月 10 日发布，是 8.3 系列的稳定版（beta.0 在 9/2、beta.1 在 9/7）。本次稳定版相对精简：特性只有一条 `build: avoid settling seen preload dependencies for performance`（#23446），避免对已见过的预加载依赖做多余的 settle，直接优化构建性能；Bug 修复包括正确处理 **CRLF 换行在 code frame 位置计算中的偏移**（#23219）、以及「只把完整的 `node_modules` 路径段视为依赖」以修复长期存在的 #17467；性能改进有一条 `proxy: pre-compile context matchers at server creation`（#23263），在 server 创建时预编译代理的上下文匹配器。同日发布的 create-vite 9.2.1 则主要是非 major 依赖的批量更新。值得注意的是 8.3 整条线的重头戏其实落在 beta 上——devtools 接入 dev server（beta.1）、顶层 `tsconfig` 选项、`closeServer`/`closePreviewServer` 钩子、接受 Rolldown 的 watch 选项（beta.0），稳定版是把这些收敛上线。

_来源：[vitejs/vite 发版记录](https://www.gitwatchman.com/track/vitejs/vite)｜[vite 8.3.0 release notes](https://newreleases.io/project/yarn/vite/release/8.3.0)_

### Microsoft Edge 153 Web 平台说明发布：CSS scroll-axis-lock 与单轴滚动容器

微软 9 月 10 日发布了 Edge 153 的 Web 平台 release notes，与 Chrome 153 对齐的一批特性正式到达用户。CSS 侧两条最实用：**`scroll-axis-lock` 属性**让开发者决定浏览器的单轴滚动锁定启发式是否生效，`none` 允许横竖同时滚动（此前想要「永远可斜向滚动」没有标准办法）；**单轴滚动容器**允许 `overflow: scroll clip` 这类「可滚动值 + clip」组合，让元素只在一个轴上成为滚动容器，从而解锁「行列头同时吸顶」的表格布局。JavaScript 侧新增 **`Iterator.join()`** 与 **`Iterator.zip()` / `zipKeyed()`**，把多个迭代器聚合成一个。Web API 侧还有 `transitionrun` 与媒体查询事件的**可互操作派发时机**（对齐 HTML 事件循环规范，与 Firefox/Safari 一致）、WebAudio 可配置渲染量子、**WebGPU `buffer_view` 特性**，以及非 XSLT 场景下**用 Rust 重写 XML 解析**。移除项：`_current` 链接目标。

_来源：[Microsoft Edge 153 web platform release notes](https://learn.microsoft.com/en-us/microsoft-edge/web-platform/release-notes/153)_

### Cognition 发布 SWE-2：FrontierCode 50.0%，价格打对折

Cognition 于 9 月 10 日发布自研编码模型 SWE-2，同步上线 Devin Desktop 与 CLI，并向 Devin Web / Fusion 铺开。核心数字：在自家 FrontierCode 1.1 Main 上得 **50.0%**，仅比 Anthropic Fable 5.1（50.9%）低 1 分，但成本**低 64%**；对比 GPT-6 Astra（53.3%）约为四分之一价格；也超过 SWE-1.7（42.0%）与 Grok 4.6（48.0%）。技术上有两点值得注意：底座是 Moonshot 的 **Kimi K3（2.8T 参数）**，Cognition 首次把 RL 配方推到万亿参数规模；并提出一种「Pareto 感知的成本惩罚」，在**单次 RL 训练中同时训出 medium/high/max 三个 effort 等级**，而不是分别训练再蒸馏合并。效率提升很明显：medium 档比 SWE-1.7 得分更高，但**轮次少 58%、平均成本低 81%**，首次真正改代码的中位步数从 48 降到 18。不过同一份发布里也写明，在更难的 Terminal-Bench 4 上 SWE-2 只有 27.3%，而 Fable 5.1 是 55.8%、Astra 是 57.9%——日常编码任务的价格优势成立，最难的 agentic 任务上仍不是前沿水平。商业模式上不开放权重也不单独卖 API，Pro（$20/月）及以上首月不限量。

_来源：[Introducing SWE-2: Pushing the Pareto Frontier](https://cognition.ai/blog/swe-2)_

### Claude Code 2.1.265–2.1.267：maxEffortLevel 上限与提示词快照开关

Claude Code 在 9 月 10 日前后连续推到 2.1.267。最重要的新能力是 **`maxEffortLevel`**：可以全局或按模型设置推理努力程度的上限，并且在**所有 provider 上强制生效**，包括 Bedrock、Vertex 和 Foundry，同时仍允许个人用户选更低档——这对控制企业账单是刚需。配套的 `--system-prompt-snapshot off` 让迭代提示词措辞的开发者每次请求都重新渲染系统提示，而不是复用会话早期记录的那份。修复方面：2.1.265 引入的 **CLAUDE_CODE_USE_GATEWAY 回归**（未设置 `ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN` 时也会强制走云网关登录，直接打断自建代理与 LLM 网关）在 2.1.266 回滚；2.1.267 修了 Cowork 在要求沙箱化的组织里定时任务启动即失败的问题。此外 ant CLI 升到 1.30.0，新增 `ant apply`——用仓库里的文件声明 agent、环境、skills、memory 与部署，先打印 plan 再执行，状态写进 `claude-lock.json`，基本就是把 IaC 的思路搬到了智能体管理上。Anthropic 当天还上线了 Claude 状态页两起短暂错误率升高事件（Mythos 5.1 / Fable 5.1 / Opus 5 一起，Sonnet 5 单独一起），均已恢复。

### Angular 同日披露两个 CVE：指令宿主绑定净化绕过与 SSR 传输缓存泄露

9 月 10 日，Angular 两个安全公告进入各漏洞库。**CVE-2026-88057** 是 `@angular/core` 与 `@angular/compiler` 的净化绕过：编译器在决定指令宿主绑定的 SecurityContext 时，依据的是**指令/组件选择器**而不是**实际的宿主元素**，当同一指令通过 hostDirectives 组合、类继承、动态组件实例化或应用到 SVG/MathML 元素上时，就会漏掉正确的消毒器，导致 `javascript:` 这类 URL 未经过滤写进 DOM 属性，形成 XSS（CWE-79，CVSS 4.0 后续影响为 Low/Low）。**CVE-2026-88059** 更隐蔽：`@angular/common` 的 `HttpTransferCache` 在 SSR + 水合、且子 HttpClient 通过 `withRequestsMadeViaParent` 委派给父级注入凭据时，子缓存会在委派前先评估匿名请求并**把带 Authorization 的响应序列化进 `ng-state` 脚本**；若该 SSR HTML 被 CDN/反代共享，后来的未登录访客就能拿到前一位用户的私有数据（CVSS 3.1 4.0）。两者修复版本一致：**22.1.0 / 21.2.20 / 20.3.28**（88059 另有 22.1.1）。

### React 19.3 余波：Rust 编译器修掉非 ASCII 源码导致的 panic

React 19.3 于 9 月 9 日发布后，社区 9 月 10 日的关注点转向了编译器侧的一个正确性修复。Rust 编译器移植里的 `get_identifier_name_with_loc` 会在 SSA 丢弃标识符名时回退到「从源码切片读取」，但它拿 **Rust `&str` 的 UTF-8 字节偏移**去切，而 `SourceLocation.index` 是 **Babel 的 UTF-16 码元位置**——两者只在源码全为 ASCII 时一致，一旦前面出现非 ASCII 字符，后续偏移就会短缺，轻则读错区间、重则直接 panic（表现为 `ValidateNoSetStateInEffects` 崩溃）。修复统一了两套索引方案。同批 React Native 侧改动包括：RuntimeScheduler.h 不再传递性地包含两个私有头文件（改为前向声明）、RCTInstance.h 移除一个把 `jserrorhandler` 拉进公共头的死 include、bridgeless RCTInstance 移除无调用方的运行时诊断标志 getter/setter，`cxxreact:jsbigstring` 被归类为公共目标。另外 v0.88.0-rc.0 的 changelog 有**三处更正**（Touchable 根导出条目重复、iOS RCTArrayBuffer 条目措辞），程序化消费 changelog 的团队需要重读该段。

_来源：[React 19.3 ships View Transitions, Rust compiler fixes non-ASCII panic](https://repojournal.com/showcase/meta/2026-09-10/react-19-3-ships-view-transitions-rust-compiler-fixes-non-ascii-panic)_

### Prisma 陷阱：npm 上的 prisma@latest 已指向不稳定的 8.x

Oday Bakkour 9 月 10 日的 dev stack 审计特别点名了一个容易踩的坑：Prisma 在 9 月 1 日打上了第一个 **8.x 开发构建**，此后 **npm 上的 `prisma@latest` 解析到的是这条不稳定的 8.x 线**，而不是 7.x 稳定系列。任何在生产安装里依赖 `@latest` 而不锁版本的项目，都可能在某次干净安装时静默拉入破坏性变更。当前稳定版是 **7.10.0**（同时提供一个兼容包，让 Prisma 7 的配置能跑在 Prisma 8 安装旁边），建议显式 pin 住 `prisma` 与 `@prisma/client` 两个包。Prisma 官方也发文回应了社区对 8.x 新迁移模型是否适合长生命周期生产应用的担忧。

### SvelteKit 的 sv CLI 用 ai-tools 取代 mcp 插件，并预告 SvelteKit 3 迁移任务

Svelte 官方 9 月月报（9 月 1 日发布、本周持续的落地）中，`sv` CLI 的 **`mcp` add-on 已被更宽的 `ai-tools` add-on 取代**（sv@0.17.0），可为 Svelte 插件（Claude Code、opencode）做整体配置，也可以逐工具挑选（MCP server、skills、sub-agents）。更关键的是 `sv@1.0.0-next.0` 重写了 `sv migrate`：现在会列出任务清单，内置一个 **`sveltekit-3` 任务**（升级依赖并把 `$lib` 重写为 `#lib`）、一个 `$app/state` 任务，把更老的迁移委托给 `svelte-migrate@1`，并对无法自动迁移的改动生成一份待办列表给开发者或智能体。新建项目也已默认使用 `#lib`（Node subpath imports）而非 `$lib`。

_来源：[What's new in Svelte: September 2026](https://svelte.dev/blog/whats-new-in-svelte-september-2026)_
