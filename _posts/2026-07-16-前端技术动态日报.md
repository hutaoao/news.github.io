今天前端社区最重磅的消息莫过于 TypeScript 7.0 的正式发布——基于 Go 语言重写的编译器带来了 8-12 倍的性能飞跃，这可能是 TypeScript 历史上最重要的一次更新。

### TypeScript 7.0 正式发布：Go 重写编译器，性能提升 8-12 倍
微软正式发布了 TypeScript 7.0，这是该语言 14 年来最大变革——将编译器从 JavaScript 移植到 Go 语言原生实现。新版本利用共享内存多线程支持及编译器优化，完整构建场景性能提升 8-12 倍，内存占用显著降低。此次移植力求保持与原代码库的结构与逻辑一致性，确保两个编译器的输出兼容。开发者可通过 `npm install typescript` 体验。
_来源：[微软 TypeScript 博客](https://devblogs.microsoft.com/typescript/) | [腾讯网](https://new.qq.com/rain/a/20260717A06G3I00)_

### ECMAScript 2026 正式获批：JavaScript 第 17 版规范发布
ECMA International 于 6 月 30 日正式批准 ECMAScript 2026（ES17），主要新特性包括：`Math.sumPrecise`（高精度求和）、`Array.fromAsync`（从异步可迭代对象构建数组）、`Error.isError`（识别错误对象）、`Map.prototype.getOrInsert` 等获取默认值方法，以及 `Uint8Array` 的 Base64/十六进制编码互转方法。这是 JavaScript 语言规范的第 17 个版本，体现了 TC39 持续稳健的迭代节奏。
_来源：[腾讯网](https://new.qq.com/rain/a/20260710A002R500) | [W3Schools](https://www.w3schools.com/Js/js_2026.asp)_

### W3C WebGPU 候选草案持续推进，1.0 标准临近
W3C 于 6 月 23 日发布了 WebGPU 的最新候选推荐草案（Candidate Recommendation Draft），这标志着 WebGPU 1.0 规范正稳步向正式标准迈进。业界预期 WebGPU 1.0 稳定版将在 2026 年内完成全浏览器兼容覆盖，届时前端开发者可在浏览器中调用接近原生的 GPU 通用计算能力，彻底打破 JavaScript 单线程的性能瓶颈，为端侧 AI 推理、3D 渲染、数据可视化等场景带来质的飞跃。
_来源：[W3C WebGPU 发布历史](https://www.w3.org/standards/history/webgpu/) | [CSDN 深度分析](https://blog.csdn.net/2303_76234920/article/details/159578937)_

### CSS Anchor Positioning 入门指南发布
Web Standards 发布了一篇关于 CSS Anchor Positioning 的入门教程，详细介绍如何通过 `anchor-name` 和 `position: anchor()` 实现工具提示（tooltip）和下拉菜单的精确定位，并涵盖溢出回退（overflow fallback）处理和浏览器兼容方案。该特性是 CSS 规范中一项重要的原生定位能力，有望大幅减少对 JavaScript 定位库的依赖。
_来源：[Web Standards](https://www.web-standards.dev/news/2026/07/getting-started-with-anchor-positioning/)_

### Chrome DevTools 迎来 Navigation API 全面支持
随着 Navigation API 逐渐取代传统的 History API，Chrome DevTools 团队在最新的 Canary 版本中加入了对 Navigation API 的完整调试支持，包括导航事件拦截、历史条目检查和跨文档导航追踪。Navigation API 相比 `window.location` 和 History API 解决了诸多痛点，提供了更可靠的拦截机制和更清晰的导航模型。
_来源：[MDN Web Docs](https://developer.mozilla.org/)_

### 「We Still Need Build Tools」——2026 年构建工具价值再审视
Web Standards 发布专题文章，重新审视在原生 ESM 和浏览器能力不断增强的 2026 年，CSS 和 JS 构建工具是否仍有立足之地。文章认为，尽管浏览器原生支持越来越多功能，但 Vite、esbuild 等工具在代码转换、HMR、优化打包等方面的价值依然不可替代，只是在选择工具时更应关注实际收益而非盲目跟风。
_来源：[Web Standards](https://www.web-standards.dev/news/2026/07/do-we-still-need-build-tools/)_

### 「In Defense of Polyfills」——Polyfill 的存续意义
一篇来自 Web Standards 的深度文章为 polyfill 辩护，指出在标准制定过程尚未完成之前，polyfill 是保持 Web 兼容性和推动新特性普及的关键手段。文章以 `CSS Anchor Positioning` 为例，说明在没有 polyfill 的情况下，开发者往往被迫采用 Hack 方案或等待漫长的浏览器兼容周期。
_来源：[Web Standards](https://www.web-standards.dev/news/2026/07/in-defense-of-polyfills/)_

### Shaders：一个面向 WebGPU 效果的跨框架设计平台
一个新发布的名为「Shaders」的设计平台，允许开发者在不编写着色器代码的情况下构建 GPU 视觉效果，并原生支持 React、Vue、Svelte 等主流框架。该平台利用 WebGPU 的后端能力，为前端开发者降低了 GPU 编程的门槛，是 WebGPU 生态工具链日趋成熟的重要标志。
_来源：[Web Standards](https://www.web-standards.dev/news/2026/07/shaders-webgpu-design-platform/)_

### Service Workers 规范更新至最新候选推荐草案
W3C 发布了 Service Workers 规范的最新候选推荐草案（2026 年 6 月 17 日版），持续推进离线能力、缓存策略和推送通知等核心 API 的标准化。Service Workers 作为 PWA 的基石，其规范稳定对于 Web 应用替代原生应用体验至关重要。
_来源：[W3C Service Workers 规范](https://www.w3.org/TR/service-workers/)_

### Temporal API 遗憾错过 ES2026，等待 ES2027
尽管社区期待已久，`Temporal`（JavaScript 全新的日期时间 API）最终还是未能赶上 2026 年 6 月的规范截稿窗口，被正式推迟到 ES2027。Temporal 被广泛视为 JavaScript 最混乱 API 之一——Date 对象的合格替代者，其延期意味着开发者仍需继续依赖 `date-fns`、`Luxon` 等第三方库至少一年。
_来源：[W3Schools JavaScript 2026](https://www.w3schools.com/Js/js_2026.asp)_
